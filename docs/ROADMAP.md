# DraftSmith 개발 계획

2026-11-24 정리. 바뀌면 이 문서와 [구현 노트](implementation-notes.md)에 함께 적는다.

## 1. 확정 사항

| 항목 | 내용 |
|---|---|
| 이름 | DraftSmith — 저장소·패키지 `draftsmith`, 명령행 `dsmith`, 파일 확장자 `.dsmith` |
| 대상 OS | macOS (Apple Silicon·Intel), Windows (x64·ARM64). 브라우저·Linux 는 대상 아님 |
| 방식 | 오픈소스 (MIT OR Apache-2.0). 혼자 쓰는 용도로 시작해 팀 공동작업으로 넓힘 |
| 개발 환경 | BEATS 와 같음 — Rust 작업공간(코어·CLI·앱), Tauri 2, 순수 JS 모듈 화면, npm 없음 |
| 원칙 | 한글 우선, 가벼움, 2D 우선(3D 대비), 건축 객체 중심, 설계 단계별 작업공간 |

## 2. 구조

```
DraftSmith 앱 (Tauri 2)
├ 화면 (ui/, OS 내장 웹엔진: macOS WKWebView · Windows WebView2)
│   ├ 메뉴·패널·입력창 — 순수 JS 모듈 + 자체 UI 부품. 한글 입력은 웹엔진이 처리
│   └ 도면 보기 — WebGL2 로 직접 그림 (표시 데이터를 GPU 버퍼에 그대로 올림)
└ Rust (draftsmith-core)
    ├ 도면 모델 · 명령 · 스냅 · 변경 이력(Loro, 예정)
    ├ DXF·DWG 입출력 (acadrust)
    └ 표시 데이터 만들기 → 바이너리로 화면에 전달 (JSON 변환 없음)
dsmith 명령행 — 같은 코어로 정보·변환·측정·회귀 시험
```

- 열린 도면은 Rust 가 들고, 화면에는 표시 데이터만 넘긴다 (BEATS 와 다른 점 — 도면이 크기 때문).
- 도면 좌표는 f64. 화면에는 도면 중심을 뺀 f32 로 넘겨 TM 좌표처럼 큰 값도 떨리지 않게 한다.
- 화면이 바뀔 때만 다시 그린다.

## 4. 설계 단계별 작업공간

| 단계 | 주요 기능 | 시기 |
|---|---|---|
| ① 대지·법규 검토 | 지적도(SHP/DXF), 대지경계, 건폐율·용적률·정북일조 사선 | M4 |
| ② 배치·매스 | 층별 외곽선 → 연면적·건폐율·용적률 실시간 | M4 |
| ③ 평면 계획 | 그리드·층·벽·문·창·실, 면적표 자동 갱신 | M3 |
| ④ 기본설계 | 벽체 구성(구조·단열·마감), 축척별 표현 | M3 |
| ⑤ 실시설계 | 상세도, 창호일람표, 실별 마감표 | M2~M4 |
| ⑥ 허가·납품 | 도면 세트 PDF, DWG 납품, 건축물대장 기준 면적표 | M4 |

공통: 명령 팔레트(⌘/Ctrl+K, 초성 검색), 커서 옆 직접 입력, 개정 구름표시.
**BEATS 연결**: 실·벽 객체를 BEATS 의 존·외피 입력으로 넘긴다 (M3 이후).

## 5. 파일 포맷 `.dsmith` (ZIP 묶음, M2)

```
manifest.json   포맷 판, 단위(mm), 좌표계, 앱 판
document.loro   도면 + 변경 이력 (공유용으로 이력 없이 저장 가능)
xrefs/          참조 도면 (읽기 전용)
thumbnails/     미리보기
```

## 6. 한글

- 예전 도면 문자 코드(CP949·조합형) 자동 변환 — acadrust.
- 도면 기본 글꼴은 앱에 넣은 OFL 글꼴 (OS 마다 기본 한글 글꼴이 달라 글자 위치가 바뀌지 않게).
- SHX 해석 + 공개 글꼴 대체 표. 한글 단선 글꼴 자체 개발(OFL, 2,350 자 → 11,172 자).
- 한글 입력은 웹엔진이 처리. 조합 중 Enter·Esc 가 명령이 되지 않게(`isComposing`). 한자 변환 지원.
- 레이어 기본 체계 KS F 1542 (원문은 저장소에 넣지 않음).

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| acadrust 가 젊은 프로젝트 (2026-02 시작) | 가져오기를 `import` 모듈 한 곳에 가둠. 문제는 원 프로젝트에 기여. ACadSharp 예비 |
| 큰 도면의 화면 전달 | 바이너리 응답 측정(M0 ①). 부족하면 보이는 영역만 나눠 보내기 |
| Loro 대형 도면 성능 | M0 ③ 실측. 부족하면 자체 변경 기록 |
| 한글 입력 예외 | M0 ④ 실기 시험 + 회귀 목록 |
| 단선 글꼴 작업량 | 2,350 자부터 단계적으로 |
| 혼자 개발할 때 범위가 늘어남 | 단계마다 마감 조건을 지키고, 다음 단계 기능을 미리 만들지 않음 |
