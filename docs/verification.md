## 6. 이번 검증에서 찾아 고친 것

1. **DXF·DWG 의 블록 정의(BLOCK·ENDBLK) 핸들이 0** — ezdxf 가 파일을 거부. AutoCAD 도 거부할 수 있는 결함. 핸들을 준다.
2. **새 시트가 건물이 아닌 전체(대지·멀리 놓은 단면도 포함) 가운데를 봄** — 그 층 벽·실·기둥·그리드 범위로.
3. **DXF·DWG 내보내기는 지금 층만 펼침** — 층이 여럿이면 파일 이름에 층 이름을 붙이고(`도면-1층.dwg`), CLI 에 `--level`.
4. **건축 객체만 있는 도면에서 「객체 0 개」 로 보임** — `dsmith info`·앱 상태 줄에 건축 객체 수.

## 7. 알려진 한계 (이번 판)

검증 뒤 고침 (§45): 무늬 해치가 HATCH 로 오감, 모든 층을 한 DWG 에 나란히, 가져온 반지름·각도 치수도 치수 객체로,
단면도 가림 처리. 남은 것:
- 단면 가림은 벽 단위 근사 (벽 일부 높이만 가리는 경우·기둥·계단 입면은 아직).
- 치수 글꼴·DIMSTYLE 세부(화살표 크기·글자 위치)는 DraftSmith 식.

## 8. 실제 기기에서 남은 확인 (사용자)

- macOS·Windows 에서 실행 (서명 전 — macOS 는 `xattr -cr DraftSmith.app`, Windows 는 SmartScreen 「추가 정보 → 실행」).
- 한글 입력(실 이름·글자 도구), 파일 대화상자(저장·내보내기·PDF), Retina·고해상도 화면에서 선 굵기.
- 실무 DWG 로 열기·고치기·다시 저장 뒤 AutoCAD 에서 열기.
- 큰 도면 화면 속도(WebGL — Linux 개발 환경은 소프트웨어 렌더라 측정하지 않음).

## 다시 하기

```sh
cargo build --release -p draftsmith-cli
B=target/release/dsmith
$B demo /tmp/v/demo.dsmith && $B info /tmp/v/demo.dsmith
$B export /tmp/v/demo.dsmith /tmp/v/demo-1층.dxf --level 1층
$B ifc /tmp/v/demo.dsmith /tmp/v/demo.ifc
$B pdf /tmp/v/demo.dsmith /tmp/v/A-101.pdf --layout "A-101 1층 평면도" --scale 1
# 검사: python -m pip install ezdxf ifcopenshell 뒤 ezdxf.recover.readfile·ifcopenshell.validate
```

# 두 번째 검증 (2026-11-26 ~ 27)

첫 검증 뒤 실무 도면(사용자 제공 DWG, 저장소에 넣지 않음)과 SHX 글꼴로 고친 것들을 다시 본 결과. 자세한 것은 구현 노트 §59 ~ §89.

## 1. 실무 도면 (모형 2,118 객체 · 보이는 도면 5.6 만 · 치수 496 · A3 틀 12 장)
- 가져오기: 건너뛴 객체 없음(OLE 는 테두리, §88). 가리개·글자 스타일·치수 스타일·폭 있는 폴리선 반영(§60 ~ §65).
- 고유 번호: 모든 객체가 DWG 핸들 그대로, 다시 가져와도 같음. DXF·DWG 로 내보냈다 읽어도 객체 수·종류·번호가 같음(§82·§83).
- PDF: 틀마다 한 쪽(§63, 19 초 → 2.1 초).

## 2. 편집 한 번의 비용 (실무 도면, 한 객체 제자리 고치기, release·Linux)

| 단계 | 처음 | 지금 |

## 3. 다른 프로그램(ezdxf)으로 내보낸 DXF 점검 (§89)
- 실무 도면·예제 건물·가끔 나오는 종류 시험 도면: ezdxf 감사 오류 0, 고친 것 0, 객체 수 일치.
- ezdxf 로 그린 그림이 우리 PDF 와 같은 모양(색은 흰 바탕 보정, 한글은 이 환경 글꼴 없음).
- 곡선 벽·돌음 계단 IFC 는 ifcopenshell 로 읽어 부피가 계산과 맞음(§77·§78).

## 4. 앱 화면 (Linux Xvfb, release)
- 실무 도면 지우기·블록 참조 지우기·옮기기 뒤 되돌리면 처음 화면과 픽셀까지 같음(§72 ~ §74).
- 디자인 토큰으로 바꾼 뒤 화면이 바꾸기 전과 픽셀까지 같음(§81). 3D 곡면 그늘(§79). 선택이 고유 번호로 유지(§84).
- 사본 합치기: 두 사본을 앱에서 따로 고쳐 저장 → `dsmith merge` 결과가 맞음(§85). 앱 안 「다른 사본과 합치기」는 이 환경에
  파일 대화상자가 없어 고르기 단계까지만(고른 뒤 처리는 시험으로, §86).

## 5. 실제 기기에서 남은 확인 (사용자)
- macOS·Windows 에서 열기 속도(상태 막대 「전달」 시간, base64 표시 여부 — §70), 한글 입력, 파일 대화상자(사본 합치기 포함).
- 내보낸 DWG 를 AutoCAD 등 다른 CAD 로 열기 — 이 환경에는 다른 DWG 읽기 도구가 없다(설치가 막힘).
