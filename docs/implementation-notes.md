# 구현 노트

결정과 근거를 번호(§)로 남긴다. 코드 주석은 이 번호를 가리킨다.

## §1 개발 환경을 BEATS 와 같게 (2026-11-24)

Rust 작업공간에 코어·CLI·앱 세 crate. 앱은 Tauri 2, 화면은 HTML·CSS·순수 JS 모듈(npm·번들러 없음).
`cargo build/test` 기본 대상은 코어·CLI 이고 앱은 `-p draftsmith-app`.
검토했다가 접은 것: 네이티브 화면 위에 투명 웹 UI 겹치기, Rust 네이티브 UI(egui·iced·Slint), Qt, GPUI —
한글 입력 안정성과 개발 부담 때문 (결정 과정은 ROADMAP 2026-11-24 판 이전 논의).

## §2 판 표시

판은 `Cargo.toml` 한 곳. `build/version.rs` 가 git 상태를 보고 「0.1.0」·「0.1.0-dev (커밋)」·「…*」 를
`DRAFTSMITH_VERSION` 으로 넘긴다 (BEATS 구현 노트 §218 과 같은 방식).

## §3 DXF·DWG 는 acadrust

순수 Rust, MPL-2.0, R12~R2018 읽기·쓰기. DWG 코드는 ACadSharp(MIT)에서 옮긴 것이라 GPL 코드가 없다
(`THIRD_PARTY_NOTICES.md` 확인). 2007 이전 도면의 `ANSI_949`·조합형을 `encoding_rs` 로 푼다 (소스 확인).
DWG 여부는 파일 머리 `AC` + 숫자로 본다.

지금 가져오는 것: LINE, LWPOLYLINE, POLYLINE(2D), CIRCLE, ARC, TEXT, MTEXT(위치·크기만).
그 밖(INSERT·HATCH·DIMENSION 등)은 `Drawing::skipped` 에 개수를 남겨 화면·CLI 에 알린다 — 실무 도면은
블록이 많으므로 INSERT 펼치기가 M0 ② 의 첫 일이다.

## §4 화면에는 바이너리 표시 데이터

열린 도면은 앱(Rust)이 들고, 화면에는 `display_data` 명령이 선분 목록 바이너리(`DSD1`)를
`tauri::ipc::Response` 로 넘긴다. 형식은 `draftsmith_core::display` 머리 주석.

- 좌표는 도면 범위 중심(origin)을 뺀 f32 — GPU f32 정밀도 문제(TM 좌표) 회피.
- 원호는 화살 높이가 도면 대각선의 1/20000 이하가 되게 8–512 조각.
- 문자는 글꼴 처리 전이라 밑줄로 자리만 (M0 ⑥).

첫 측정 (2026-11-24, 클라우드 개발 컨테이너, 4 코어):
`dsmith sample 100000` (선 4 만·원 4 만·폴리선 1 만·한글 문자 1 만, DXF 16.6 MB) →
읽기 358 ms, 선분 41 만 개 펼치기 14 ms, 바이너리 3 ms (8.2 MB).
화면(Chromium, 소프트웨어 WebGL)에 올리기 18 ms. 실제 WKWebView·WebView2 와 Tauri 전달 시간은 실기 측정이 남았다.

## §5 블록 참조(INSERT) 펼치기 (2026-11-24)

**고친 오류**: acadrust 의 `entities()` 는 블록 정의 안 객체까지 모두 돌려준다. 처음 골격은 이것을 그대로 써서
블록 안 모양이 원점 근처에 한 번 더 그려졌다. 이제 `model_space_entities()` 에서 시작하고, 블록 안 객체는
`entities_in_block(이름)` 으로 참조마다 펼친다.

변환 순서 (블록 안 좌표에서 바깥으로):
`−기준점 → 축척(x, y) → 회전 → 삽입점(배열이면 칸마다) → 돌출 방향(OCS) → 바깥 블록의 변환`.

- **돌출 방향 −Z**: 대칭 복사한 블록·원·폴리선에 흔하다. X 를 뒤집는 변환으로 처리한다. 기울어진 돌출 방향은 무시.
- **원·호**: 회전·균등 축척이면 원·호 그대로, 대칭이 들면 원은 원·호는 시작·끝 각을 `β − 끝, β − 시작` 으로
  (β = 변환 뒤 x 축 방향). 비균등 축척이면 타원(켤레 반지름 u·v 꼴)으로 바꾼다 — 아무 아핀 변환에도 닫혀 있다.
- **폴리선 불지**: 등각이면 그대로, 대칭이면 부호만 뒤집고, 비균등 축척이면 호를 32 조각으로 펼친 뒤 변환.
- **문자**: 높이는 글자 위쪽 방향이 늘어난 만큼, 방향은 진행 방향이 돈 만큼.
- **레이어·색 물려받기**: 블록 안 「0」 레이어 객체는 참조의 레이어로, ByBlock 색은 참조의 색으로.
- **속성값(ATTRIB)**: 이미 세계 좌표라 바깥 변환만 건다. 숨김 속성은 뺀다.
- **안전장치**: 블록 안 블록 깊이 16, 자기 자신을 부르는 정의는 건너뛰고 `skipped` 에 「블록 순환·깊이 초과」.
  펼친 객체가 2 천만 개를 넘으면 멈춘다. acadrust 가 너무 큰 배열을 거부하면 「배열 블록 한도 초과」.
- 가져오지 않은 객체 이름은 acadrust 의 `entity_type()` (Debug 출력 대신 — 빠름).

측정용 도면에 문 블록(「문-900」, 한글 블록 이름, 칸마다 번갈아 대칭)을 넣었다.
DXF·DWG 왕복 모두 펼친 결과가 메모리에서 바로 펼친 것과 개수·범위가 같다 (시험 `grid_round_trips_through_*`).

측정 (11 만 객체, 블록 참조 1 만 개 펼침): DXF 17.3 MB 읽기 544 ms / DWG 2.1 MB 읽기 239 ms,
선분 42 만 개 펼치기 14–18 ms.

## §6 해치·치수·솔리드·스플라인·문자 (2026-11-24)

- **해치**: 경계(선·원호·타원호·스플라인·불지 폴리선 변)를 고리로 펼친다. 시계 방향 원호 변은 각도가
  거울상으로 저장되므로 `−시작 → −끝` 시계 방향으로 그린다. 솔리드·그러데이션이면 채움(`Shape::Fill`),
  무늬면 무늬 선(`Shape::Segments`). 무늬 선은 DXF 에 저장된 값(축척·각도 적용됨)으로 만들고 짝홀 규칙으로
  경계 안만 남긴다 (경계 위 선은 반열림 규칙). 한 해치에 20 만 선분을 넘으면 무늬 대신 경계선만 그리고 알린다.
- **채움 삼각형**: 고리마다 다른 고리에 몇 번 싸였는지(깊이)로 바깥·구멍을 나누고 earcut 으로 분할 (짝홀 규칙).
- **치수**: 치수가 그려 둔 익명 블록(`*D…`)을 펼친다 (치수 문자·화살표 SOLID 포함). 블록이 없는 파일이면
  선형·평행 치수만 간단히 그린다 (치수선·보조선·45° 사선·측정값, 글자 높이는 길이의 1/20).
- **SOLID**: 꼭짓점 순서 1-2-4-3 으로 채움.
- **스플라인**: NURBS de Boor (가중치 포함), 매듭 구간마다 16 조각. 조정점이 없으면 맞춤점을 잇는다.
- **문자**: TEXT 맞춤(가로 왼·가운데·오른, 세로 바탕선·아래·가운데·위)과 맞춤점, MTEXT 붙는 점 1–9,
  폭 배율. MTEXT 서식 코드(`\P` 줄바꿈, `\f…;` 글꼴, `\H…;` 크기, `\S…;` 쌓기, `\U+XXXX` 등)와 `%%c/%%d/%%p`
  를 걷어 내고 보이는 글자만 남긴다. 대칭한 블록 안 문자는 뒤집지 않고 읽을 수 있게 둔다 (MIRRTEXT=0).
- **화면**: 선·채움은 WebGL2 (`DSD2` 형식에 삼각형 추가), 문자는 그 위 Canvas 2D 층에 글꼴로 (`DST1` 형식,
  `text_data` 명령). 3 화면 점보다 작은 글자와 화면 밖 글자는 그리지 않는다. 글꼴 크기 = 도면 글자 높이 × 1.35
  (도면 글자 높이는 대문자·한글 높이). 공개 글꼴 내장은 다음 일 — 지금은 OS 한글 글꼴.

### 실제 앱 실행 확인 (Linux, 가상 화면)

앱을 `draftsmith-app 도면.dwg` 처럼 경로를 넘겨 실행하면 바로 연다 (`startup_file` 명령 — 파일 연결에도 쓴다).
처음 실행에서 Linux(WebKitGTK)는 Tauri 바이너리 응답이 ArrayBuffer 가 아니라 숫자 배열로 와서 그리지 못했다.
화면에서 ArrayBuffer·Uint8Array·숫자 배열을 모두 받게 고치고, 숫자 배열(JSON 대체 경로)이면 상태 막대에
「느린 경로」 라고 띄운다. macOS·Windows 에서 빠른 경로인지 이것으로 확인한다.

측정용 도면 10 만 (펼치면 15 만 객체, 블록 8 천, 해치 8 천, 치수 8 천):
CLI 읽기 425 ms · 선분 41 만 펼치기 26 ms. 앱(Linux, 느린 경로): 읽기 445 ms · 전달 663 ms (9.6 MB) · 올리기 71 ms.

## §7 스냅·측정·내장 글꼴·최근 파일 (2026-11-24)

- **스냅 색인** (`draftsmith_core::snap`): 켜진 레이어 객체의 끝점·중간점(불지 호는 호 가운데)·중심·사분점·
  문자 삽입점, 솔리드 꼭짓점을 R*-tree(rstar)에 넣는다. 해치 무늬 선은 너무 많아 뺀다. 도면을 열 때와
  레이어를 켜고 끌 때 다시 만든다. 커서에서 가장 가까운 점이 화면 12 점 안이면 붙는다 (종류 우선순위 없음).
- **M0 ⑤ 스냅 계산 위치**: 마우스가 움직일 때마다 Rust `snap` 명령을 부르고, 한 번에 하나만 보내며 밀린 것은
  마지막 위치만 보낸다. 지연 중앙값을 커서 좌표 옆에 보인다. Linux(느린 경로)에서 약 9 ms — 쓸 만하다.
  macOS·Windows 실측 후 결정한다 (화면 쪽으로 옮길지).
- **측정 도구** (`ui/js/measure.js`, 단축키 D): 두 점 → 거리·ΔX·ΔY·각도. 끌기는 화면 이동, 제자리 누르기만 도구 클릭.
- **단축키는 자판 위치(`e.code`)로** — 한글 입력기가 켜져 있어도 같은 자리에서 동작. 조합 중이면 무시.
- **내장 글꼴**: Pretendard 1.3.9 Regular·SemiBold woff2 (npm `pretendard`, SIL OFL 1.1, `ui/fonts/` 에 라이선스).
  화면과 도면 문자 모두 이것을 먼저 쓴다. 글꼴을 읽은 뒤 문자를 다시 그린다.
- **최근 파일**: 앱 설정 폴더 `recent.txt` (최대 12 개, 없는 파일은 목록에서 뺌). **끌어 놓기**로 열기.
- 레이어 목록은 쓰는 객체가 없는 레이어를 숨긴다.

### 실제 앱 조작 확인 (Linux 가상 화면, xdotool)

D → 기둥 원 근처 누르기 → 다음 칸 기둥 근처 누르기: 스냅 표시(사분점 ◇)·점선 측정선·길이 표지가 그려지고
상태 막대에 「거리 5,850.0 · ΔX 5,850.0 · ΔY 0.0 · 각도 0.0°」.

## §8 고르기·속성 (2026-11-24)

- **고르기 색인** (`draftsmith_core::pick`): 켜진 레이어 객체의 경계 상자를 R*-tree 에 넣어 후보를 줄이고,
  후보는 실제 모양까지의 거리로 고른다 (화면 6 점 안). 채움은 안쪽을 눌러도, 문자는 글자 상자 안을 눌러도 고른다.
  같은 거리면 나중에 그린(위에 있는) 객체.
- **속성**: 종류·레이어·색(레이어 색인지)·길이·각도·점 좌표·반지름·둘레·호 길이·꼭짓점 수·면적·문자 내용·높이.
  면적은 도면 단위(`$INSUNITS`)로 ㎡·평도 함께 (1 평 = 3.305785 ㎡). 단위가 없으면 국내 관례대로 mm 로 보고 밝힌다.
- **강조 표시**: 고른 객체의 외곽 선분을 도구 층에 굵게 (최대 2 만 선분).
- 기본 도구가 고르기, D 로 측정, Esc 는 측정 끝·고르기 풀기. 도면을 열거나 레이어를 바꾸면 고르기를 푼다.
- 치수는 펼친 조각(선·문자·화살표)이 따로 골라진다 — 치수 하나로 묶는 것은 편집(M2) 때 객체 모델과 함께.

## §9 선 종류 (2026-11-24)

- 선 종류 표의 무늬(대시 길이: 양수 선, 음수 빈칸, 0 점)를 읽는다. 빈칸이 없는 것(CONTINUOUS 등)은 실선.
  복합 선 종류의 글자·모양 요소는 아직 그리지 않고 길이만 따른다.
- 객체 선 종류: 비었거나 ByLayer 면 레이어 선 종류, ByBlock 이면 블록 참조의 것, 아니면 이름으로.
- 무늬 배율 = 전역 LTSCALE × 객체 배율 × 블록 축척 (블록 안 객체는 블록과 함께 커진다).
- 그리기: 선·원·호·타원은 한 조각, 폴리선은 꼭짓점마다 무늬를 새로 시작 (AutoCAD PLINEGEN 끔과 같음).
  한 조각에 무늬가 2 천 번을 넘거나 무늬가 허용 오차보다 작으면 실선으로 (화면에서 어차피 실선처럼 보임).
- 채움·해치 무늬·문자에는 선 종류를 걸지 않는다.
- 측정용 도면에 CENTER 선 종류 레이어(A-GRID)와 칸마다 중심선을 넣었다 — DXF·DWG 왕복 시험 통과.

## §10 PDF 출력 (2026-11-24)

- `draftsmith_core::pdf` (krilla 0.8, MIT/Apache). 선·채움은 화면용 표시 데이터(`display::segments`)를 그대로
  써서 선 종류·곡선 펼치기가 화면과 같다. 색마다 경로 하나로 묶어 파일이 작다 (작은 평면 8 KB).
- 문자는 내장 Pretendard Regular(OTF, `crates/draftsmith-core/fonts/`, OFL)를 **부분 삽입** — 쓴 글자만 들어가
  한글이어도 작다. 가로 맞춤용 글자 폭은 ttf-parser 로 글꼴 advance 를 더한다. 글꼴 크기·줄 간격·세로 맞춤은
  화면과 같은 규칙 (글자 높이 × 1.35, 5/3).
- 설정: 용지 A4–A0·방향, 축척(1:N, 도면 단위 mm 기준 — `$INSUNITS` 로 환산) 또는 용지에 맞춤, 범위(도면 전체·
  지금 화면 — 범위 밖은 잘라냄), 컬러/흑백, 선 굵기 0.18 mm. 범위는 용지 가운데에.
- 종이 색 규칙: 흰색 → 검정, 밝은 색은 어둡게 (화면 흰 배경과 같음). 흑백이면 선·글자·채움 모두 검정
  (AutoCAD monochrome.ctb 와 같음 — 처음엔 채움을 회색으로 했으나 치수 화살표까지 회색이 되어 바꿈).
- 앱: 「PDF」(⌘P / Ctrl+P) 설정 칸 → 저장 대화상자. CLI: `dsmith pdf 도면 출력.pdf --paper A3 --scale 100 --mono`.
- Rust MSRV 를 krilla 에 맞춰 1.92 로.

### 함께 고친 것
- 설정 칸이 닫히지 않던 것: 작성자 CSS 의 `display: grid` 가 `hidden` 을 덮었다 → `[hidden] { display: none !important }`.
- 흰 배경 설정이 앱을 다시 열면 사라지던 것 (WebKitGTK localStorage): 앱 설정 폴더 `settings.txt` 에
  `이름=값` 으로 저장하는 `get_setting`/`set_setting` 명령으로 바꿨다 (최근 파일과 같은 곳).

## §11 선 굵기 (2026-11-24)

- 객체 선 굵기: ByLayer 면 레이어 굵기, ByBlock 이면 블록 참조의 것, Default 면 없음, 값이면 그 값 (1/100 mm).
  블록 안 「0」 레이어 객체는 참조의 레이어를 받으므로 그 레이어 굵기를 쓴다 (치수 블록 안 선이 치수 레이어 굵기로).
- 표시 데이터 `Segments.weights` 에 선분마다 굵기를 담는다 (바이너리에는 넣지 않음 — 화면은 아직 1 화면 점).
- PDF: (색, 굵기) 마다 경로 하나. 굵기가 없으면 출력 기본 굵기(0.18 mm), 있으면 그 값(최소 0.05 mm).
- 색 기준 펜 굵기(CTB 출력 스타일)는 M4 에서.

## §13 배치(종이 공간)·뷰포트 (2026-11-24)

- 읽기: 배치 객체(Layout)마다 블록 기록(`*Paper_Space…`)의 객체를 펼쳐 종이 객체로, VIEWPORT 는 뷰포트로 모은다.
  모형(Model) 배치와 빈 배치는 뺀다. 탭 순서로 정렬.
- 종이 전체 뷰포트(번호 1)는 뺀다. **DWG 는 뷰포트 번호를 저장하지 않아** 읽을 때 순서대로 번호가 붙는데,
  AutoCAD 는 이것을 늘 배치의 첫 뷰포트로 두므로 같은 규칙이 맞는다. 다른 프로그램이 종이 전체 뷰포트 없이 쓴 DWG 는
  첫 뷰포트가 빠질 수 있다 (측정용 도면도 처음엔 그래서 DWG 왕복에서 뷰포트가 사라졌다 → 종이 전체 뷰포트를 먼저 넣음).
- 꺼진 뷰포트, 3D 방향 뷰포트(보는 방향이 +Z 가 아님)는 뺀다 (3D 는 알림). 비사각 자르기 경계는 아직 사각형으로.
- 모형 → 종이 변환: `−대상점 → 비틀기(−각) → −보는 가운데 → ×(높이/보는 높이) → +종이 가운데`. 비틀기 부호는 실제
  비튼 도면으로 확인이 남았다.
- 합치기(`layout::compose`): 뷰포트마다 모형 객체를 변환해 뷰포트 사각형에 다 들어가면 그대로, 다 밖이면 버리고,
  걸치면 선은 Liang–Barsky 로 잘라 선분 묶음, 채움은 Sutherland–Hodgman 으로 자른 고리, 문자는 기준점이 안이면 둔다.
  뷰포트에서 얼린 레이어는 뺀다. 결과는 종이 좌표(mm) 의 보통 도면이라 화면·고르기·스냅·PDF 가 그대로 쓴다.
  뷰포트를 먼저, 종이 객체를 나중에 쌓는다.
- 앱: 도면 아래 「모형 | 배치…」 탭. 배치를 고르면 PDF 축척이 1:1 로 바뀐다. CLI: `dsmith pdf … --layout 이름 --scale 1`,
  `dsmith info` 에 배치 목록.
- PDF 는 범위를 정했을 때만 잘라낸다 (도면 전체를 자르면 경계 위 도곽선이 반쯤 잘려 안 보였다), 자를 때는 1 mm 여유.

## §14 복구 읽기·옛 DXF 한글 (2026-11-24)

  처음 오류를 알린다. (잘린 DXF 는 복구도 실패 — 정상. 값 하나가 깨진 DXF 는 acadrust 가 엄격 모드에서도 넘어갔다.)

## §15 화면 선 굵기 보기 (2026-11-24)

- 표시 데이터 형식을 `DSD3` 으로: 끝에 선분마다 굵기(u8, 1/100 mm, 0 = 기본)를 붙였다.
- 화면: 「선 굵기」(W) 를 켜면 선분마다 사각형(삼각형 2 개)을 GPU 인스턴싱으로 그린다 — 인스턴스 하나가 선분 하나,
  꼭짓점 셰이더가 `gl_VertexID` 로 모서리를 정한다. 끄면 예전처럼 1 화면 점 `LINES` (가볍다).
- 두께는 확대와 무관하게 굵기(mm) × 4 화면 점, 최소 1 점 (AutoCAD LWT 처럼 화면 점 고정). 기본 굵기는 0.25 mm 로 본다.
  꺾인 곳 틈이 보이지 않게 선분 끝을 반 굵기만큼 늘린다.
- 설정은 앱 설정 폴더에 기억 (`lwt`).

## §16 색 기준 출력 스타일 (CTB) (2026-11-24)

- 객체마다 색 번호(ACI)를 풀어 둔다 (`Entity::aci`): 색 번호면 그것, ByLayer 면 레이어 색 번호, ByBlock 이면 블록 참조의
  것. 트루컬러는 없음. 표시 데이터 `Segments` 에 선분·삼각형마다 색 번호를 담는다 (바이너리에는 넣지 않음).
- `.ctb` 읽기 (`draftsmith_core::ctb`): 머리 60 바이트 뒤 zlib → 글. `plot_style{ 번호{ color= lineweight= screen=
  color_policy= } }`, `lineweight{ 번호=mm }`. 번호 0 이 색 1. 색 값 −1·−1006632961 은 「객체 색」, 굵기 번호 255 는
  「객체 굵기」. color_policy 의 2 비트는 회색조, screen 은 농도(흰색 쪽으로 섞음).
- PDF: 출력 스타일이 있으면 색 번호마다 펜 색·굵기가 앞선다 (펜 굵기 → 객체 굵기 → 기본 0.18 mm). 펜이 「객체 색」 이면
  흰색(색 7)만 검정으로. 흑백 선택이 가장 우선.
- 앱: PDF 설정 칸 「출력 스타일」 에서 CTB 파일을 고르면 기억한다 (`ctb` 설정). CLI: `dsmith pdf … --ctb 파일.ctb`.
- 시험: 글로 만든 CTB(zlib) 로 펜 해석·적용 확인. **실제 AutoCAD CTB 파일로는 아직 확인하지 못했다** — 사무소 CTB 로 확인 필요.

## §17 DraftSmith 파일 `.dsmith` (2026-11-24)

## §19 건축 객체 → 평면 선 (2026-11-24)

`arch::ArchModel` 에 층·벽·개구부(문·창)·실·그리드·대지를 저장하고, 평면 선은 저장하지 않고 그때그때 만든다
(`archgen::with_arch`). 그래서 벽 두께를 고치면 문·창·실·해치가 함께 따라온다. 만드는 규칙:
- 벽: 중심선 ± 두께/2. 끝이 다른 벽 끝과 만나면 L 자 맞댐(두 면 연장선 교점), 다른 벽 몸통에 닿으면 T 자(그 벽 면에서 자름).
  단면 해치는 `A-WALL-PATT` 에 칠.
- 문: 벽을 끊고 문짝 선과 90° 여는 호(`A-DOOR`), 창: 벽을 끊고 유리선 두 줄(`A-GLAZ`). 기호(D1, W1 …)는 폭·높이가
  같은 것끼리 같은 번호.
- 실: 경계 다각형(`A-AREA`), 가운데에 이름과 면적 ㎡·평(`A-AREA-IDEN`). 「실」 도구는 누른 점에서 720 방향으로
  반직선을 쏴 처음 닿는 벽 안쪽 면으로 경계를 만든다 (직교 평면에서 맞는 단순한 방법 — 사선·곡면 벽은 나중에).
- 그리드: 1 점 쇄선(`A-GRID`)과 양 끝 기호 원(`A-GRID-IDEN`). 그리드 세트는 간격 목록으로 X·Y 를 한 번에.
- 고르기: 만든 선마다 주인(종류, 번호)을 기억해 누르면 그 건축 객체를 고르고, 속성 중 「:고침」 붙은 값은 바로 고친다.
- 건축 객체 편집은 모델 전체를 `Op::Arch{old,new}` 로 남긴다 (모델이 작아 이것이 단순하고 안전).
- 표(§22)와 3D(§24)도 같은 모델에서 나온다.

## §25 작도 화면 (2026-11-24)

- 명령줄이 늘 초점을 가진다: 도면을 눌러도 곧바로 칠 수 있다. 명령은 AutoCAD 단축(L·PL·M·CO …)과 한글 이름(선·이동 …)
  둘 다, ⌘K 팔레트는 이름·단축·초성(ㄱㄸ → 간격띄우기)으로 찾는다. 빈 Enter·Space·오른쪽 누르기는 「마치기」, 도구가
  없으면 지난 명령 되풀이 (AutoCAD 와 같음). 글을 받는 단계(글자·실 이름·그리드 기호)에서는 Space 가 그냥 띄어쓰기.
- 점 입력: 누르기(스냅·직교 적용) 또는 `x,y`·`@dx,dy`·`@거리<각`·`거리`(커서 쪽으로).
- 스냅은 끝점·중간점·중심·사분점·삽입점(F3), 직교는 F8 또는 Shift 누른 동안.
- 고르기: 누르기(Shift 더하기·빼기), 왼→오른 끌기는 창(안에 다 든 것), 오른→왼은 걸침. 화면 이동은 가운데 버튼·
  Space+끌기·트랙패드. 수정 도구는 고른 것이 없으면 먼저 고르게 한다.
- 편집은 모두 Rust `edit` 명령 하나 → 돌아온 상태(DocState)로 옆 칸을 다시 그린다. 표시 데이터 기준점이 바뀌어도
  보던 화면이 움직이지 않게 기준점 차이만큼 보정한다.
- 저장 안 한 변경이 있으면 새 도면·열기·창 닫기 전에 묻는다 (rfd 대화상자 — 창 닫기는 Rust 창 이벤트에서).

## §26 치수·글자 (2026-11-24)

(치수는 §28 에서 치수 객체로 바뀌었다.) 치수·글자 크기는 글자 높이(기본 250 = 1:100 에서 2.5 mm)에 비례.
글자 도구는 명령줄로 받아 한글 입력기가 그대로 동작하고, Enter 마다 다음 줄로 이어 쓴다.

## §27 자르기·연장·모깎기·해치 (2026-11-24)

`modify` — 선·호·원·폴리선(불지 포함)을 조각(선분·호) 열로 보고, 조각 k 의 매개변수 t 를 이어 붙인 전체 매개변수
위에서 처리한다. 경계는 화면에 보이는 모든 객체(건축 객체가 만든 벽선 포함) — AutoCAD 「빠른 자르기」 와 같다.
- 자르기: 누른 점에서 가장 가까운 매개변수를 찾고, 그 양옆 교점 사이를 없앤다. 열린 것은 0~2 토막, 닫힌 것(원·닫힌
  폴리선)은 교점이 둘 이상일 때 한 토막(원은 호)으로.
- 연장: 누른 점에 가까운 끝 조각을 무한 직선·온전한 원으로 늘려, 끝 너머 가장 가까운 교점까지.
- 모깎기: 지금은 선 두 개. 두 직선 교점에서 고른 쪽 방향으로 접점 거리 r / tan(φ/2), 반지름 0 이면 모서리.
- 해치: 누른 점을 품은 가장 작은 닫힌 폴리선·원, 없으면 점에서 720 방향 반직선이 처음 닿는 선들로 경계를 만든다
  (실 찾기와 같은 단순한 방법). 무늬는 SOLID·사선·격자·콘크리트, 간격은 도면 단위.
- 편집은 `Editor::reshape` — 바꾸기·더하기·지우기를 한 묶음 작업으로 (되돌리기 한 단계).
- 건축 객체가 만든 선은 자르지 않는다 (속성으로 고친다).

## §28 치수 객체 (2026-11-24)

치수는 건축 모델의 `Dim`(두 점, 치수선까지 거리, 글자 높이, 글자 바꾸기) — 평면 선처럼 그때그때 펼친다.
값은 늘 두 점 길이에서 새로 세어 쉼표를 넣고(12,000), 「글자」 칸에 `<>` 를 쓰면 그 자리에 길이가 들어간다.
옮기기·지우기·속성 고치기는 다른 건축 객체와 같다. 층에 속해 층별 시트에 그 층 치수만 나온다.
끝점이 그리드 선·기둥·벽 위면 그 객체에 묶는다(`Anchor` — 객체 좌표계의 앞·왼쪽 거리). 한 점이 여럿에 걸리면
그리드 > 기둥 > 벽, 같은 종류면 치수 방향과 가장 직각인 것 (가로 치수 끝은 세로 그리드 — 교점에서도 맞게).
묶인 객체를 옮기면 치수 값이 따라 바뀐다. 치수를 옮기면 치수선만 옮긴다(끝점은 묶인 객체를 따름).
연속 치수: 치수 하나를 넣은 뒤 다음 점만 누르면 같은 치수선으로 이어 간다 (N 새 치수, Enter 끝).
내보낼 때는 DIMENSION 으로 (§31). 남은 것: 모형 선(벽이 아닌 객체)에 묶기, 누적 치수.

## §29 기둥·계단·도면 목록 (2026-11-24)

- 기둥: 사각(폭·깊이·회전), 평면은 외곽선(`A-COLS`) + 칠(`A-COLS-PATT`), 3D 는 층고만큼.
- 계단: 곧은 계단 a→b, 폭·단 수. 평면은 외곽·디딤판 선·오름 화살표·「UP」(`A-STRS`), 속성에 단 높이(층고/단 수)·
  디딤판 깊이, 3D 는 단마다 상자. 꺾인 계단·끊김선·법규(단 높이 ≤ 200 등) 검토는 남음.
- 층 복사는 기둥·계단도 함께. 층을 지우면 그 층 치수·기둥·계단도 지운다.
- 표 서랍에 「도면 목록」(배치 순서, 「번호 도면명」 이름을 나눠 번호·도면명, 시트의 층).

## §30 블록 (2026-11-24)

`Drawing::blocks` 에 블록 정의(이름, 기준점 원점 객체들), 도면에는 `Shape::Insert`(이름·삽입점·x·y 배율·회전) 한 객체.
화면·PDF·시트·내보내기에는 `archgen::with_arch` 가 펼친 객체를 덧붙인다 (건축 객체 선과 같은 길, 주인 ("block", 참조 번호)).
그래서 펼친 선을 누르거나 상자로 고르면 참조 하나가 골라지고, 이동·회전·대칭·복사는 참조에 건다. 참조의 대칭은
y 배율을 뒤집고 각도를 거울 쪽으로 (M·R(θ)·S = R(2α−θ)·S(sx, −sy)). 블록 안 레이어 「0」 객체는 참조 레이어·색을 따르고,
블록 안 블록은 8 단까지. 만들기(B)는 블록 정의 추가·고른 객체 지우기·참조 넣기를 한 작업으로 (되돌리기 한 단계),
펼치기(X)는 참조를 안의 객체로 바꾼다. 가져오기·내보내기는 §31.

## §31 블록·치수 가져오기·내보내기 (2026-11-24)

- 내보내기(`export::to_document`)는 이제 모형 도면을 받는다. 블록 정의는 BLOCK, 참조는 INSERT(배율·회전 그대로),
  치수 객체는 DIMENSION(정렬 — 정의점 두 개, 치수선 점, 측정값, 글자 바꾸기는 user text 로 `<>` 그대로) 과
  그 모양(선·눈금·글자)을 담은 익명 블록 `*D1…` 로 — AutoCAD 등은 치수로 고르고, 블록을 그대로 그린다.
  그 밖의 건축 객체 선은 펼친 선으로.
- 가져오기는 모형 공간의 블록 참조 중 단순한 것(배열 아님, 평면 +Z, 보이는 속성값 없음)을 `Shape::Insert` 로 살린다.
  정의는 처음 만날 때 기준점이 원점이 되게 펼쳐 담고(안의 블록은 펼친 채), 레이어 「0」·ByBlock 색은 참조를 따른다
  (ByBlock 선 종류·굵기는 아직 잃는다). 나머지(배열·속성값·기울어진 참조)는 지금처럼 펼친다.
- 다시 읽으면 블록은 블록으로, 치수는 치수 객체로 돌아온다 (§32).
- 블록을 모르는 곳(CLI 보기·PDF·측정)은 `archgen::with_arch` 나 `block::flatten` 으로 펼쳐서 쓴다.

## §32 치수 가져오기·회전 치수 (2026-11-24)

- 치수 객체에 `rotation`(회전 치수 방향 — 가로 0, 세로 π/2. 없으면 정렬 치수)과 `layer` 를 더했다. 회전 치수는 두 점을
  그 방향에 내린 길이를 재고, 치수선은 a 에서 왼쪽(n)으로 offset 인 직선. 모양 계산은 `Dim::geom` 한 곳에서
  (평면 선·속성·옮기기·내보내기가 함께 쓴다).
- 가져오기: 모형 공간의 선형(회전)·정렬 DIMENSION(평면 +Z)을 치수 객체로 — 정의점 두 개, 치수선 점에서 offset,
  글자 높이는 치수 블록(*D) 안 글자에서(없으면 DIMTXT × DIMSCALE), 바꾼 글자는 서식 코드를 걷어 그대로(`<>` 유지),
  레이어 이름도. 지금 층(없으면 「1층」)에 넣는다. 각도·반지름·좌표 치수는 지금처럼 *D 블록을 펼친 선으로.
- 그래서 가져온 치수도 고르고·옮기고·글자를 고칠 수 있다. 대신 끝 모양(화살표·사선)과 쉼표 없는 값은 원래대로
  따른다 (§36). 글꼴·소수 자리 같은 나머지 치수 스타일은 아직.
- 내보내기: 회전 치수는 선형 DIMENSION(회전각), 정렬 치수는 정렬 DIMENSION.

## §33 그립 편집·모따기·폴리선 모서리 (2026-11-24)

- 그립: 객체를 고르면 손잡이(파란 네모)가 보이고, 손잡이를 누른 뒤 옮길 곳을 누르면(스냅·직교·`@dx,dy` 입력 됨,
  Esc 취소) 그 점만 고친다 — AutoCAD 처럼 누르고·누르기 (끌기는 상자 고르기와 겹쳐서).
  - 모형 객체(`grip::grips`/`move_grip`): 선 끝·가운데(옮김), 폴리선 꼭짓점, 원 중심·반지름, 호 중심·끝·가운데
    (세 점을 지나는 호로 다시), 타원·문자·블록 참조 기준점.
  - 건축 객체(`archgen::arch_grips`, `ArchReq::Grip`): 벽 끝·가운데, 그리드 끝, 기둥 가운데, 계단 끝, 치수 끝(그 자리
    객체에 다시 묶음)·치수선, 실·대지 꼭짓점, 문·창 가운데(벽을 따라만).
  - 고른 객체 50 개까지만 손잡이를 보인다.
- 모따기(CHA): 두 선을 교점에서 d1·d2 떨어진 곳에서 잘라 선으로 잇는다 (`500` 또는 `500/300`).
- 폴리선 모서리: 모깎기·모따기에서 같은 폴리선의 두 변을 누르면, 그 사이 꼭짓점(앞뒤 변이 직선)을 호(불지)나
  사선으로 바꾼다 (`modify::corner_polyline`). 꺾이는 방향에 따라 불지 부호를 정한다.

## §34 꺾인 계단·도면 목록 시트 (2026-11-25)

- 꺾인(ㄱ자) 계단: 계단에 꺾는 점 `mid`(중심선)를 두면 두 줄기와 참(계단 폭 정사각형)이 된다. 줄기는 참 반 폭만큼
  짧아지고, 단 수는 두 줄기 길이 비례로 나눈다 (`Stair::flights`). 평면은 줄기마다 외곽·디딤판 선, 참 외곽,
  중심선을 따라 꺾인 오름 화살표. 3D 는 단마다 상자, 참은 첫 줄기 끝 높이. 줄기가 폭보다 짧으면 거절.
  계단 도구는 두 점 뒤 Enter 면 곧은 계단, 셋째 점을 누르면 꺾인 계단. 손잡이에 꺾는 점도.
- 도면 목록 시트: 시트 만들기에서 종류 「도면 목록」(또는 SHL). 뷰포트 없이 종이에 모든 시트의 목록 표
  (순번·도면 번호·도면명·축척·층)를 합칠 때마다 새로 그린다 (`Layout::list`, `sheet::list_table`) — 시트를
  더하거나 지우면 목록이 따라 바뀐다. 축척은 첫 뷰포트에서 셈.
- 새 시트의 층은 지금 층이 기본.

## §35 뷰포트 편집·손잡이 끌기 (2026-11-25)

- 시트 탭에서 옆 칸 「뷰포트」: 축척(1:N, 표준 축척 목록), 종이 위 크기·위치, 모형에서 보는 가운데를 바로 고치고,
  「모형에 맞춤」 은 그 층 모형 전체가 들어오는 가장 작은 표준 축척과 가운데로 (`sheet::edit_viewport`, 여유 8 %).
  화면에는 뷰포트 테두리를 파란 점선으로. 첫 뷰포트 축척이 바뀌면 표제란의 「1:N」 글자도 바꾼다.
- 배치 하나 바꾸기는 `Editor::set_layout`(`Op::Layouts`) — 되돌리기 한 단계. 시트에서도 되돌리기·다시 하기가 된다
  (되돌리다 시트가 없어지면 모형으로).
- 손잡이 끌기: 손잡이 위에서 끌기를 시작하면 상자 고르기 대신 손잡이를 옮기고, 놓는 곳에 스냅. 누르고·누르기도 그대로.

## §36 치수 종류·스타일·누적 치수 (2026-11-25)

- 치수 종류 `DimKind`: 선형(정렬·회전), 반지름(R), 지름(Ø), 각도(°). 반지름·지름은 a 중심·b 원 위 점, 각도는
  꼭짓점·두 반직선 위 점·호 반지름(offset). 각도는 두 반직선 사이 작은 쪽 호, 반직선이 호까지 안 닿으면 보조선.
  도구: DRA·DDI(원·호를 누르면 누른 쪽으로), DAN(두 선 → 교점 → 호 자리). 원·선 모양은 `shape_at` 명령으로 읽는다.
- 끝 모양(`arrow` — 사선/화살표)과 쉼표(`plain`)를 치수마다 둔다. 새 치수의 기본은 「치수 스타일」(DST, 설정 파일에 기억),
  고른 치수는 속성 칸에서. 가져온 치수는 원래 끝이 SOLID·해치면 화살표, 값은 쉼표 없이(AutoCAD 기본 단위 형식).
- 누적(기준선) 치수: 치수 하나 뒤 `B` 를 치면 다음 점들을 첫 점에서 재고 치수선을 글자 높이 3 배씩 바깥으로 (`C` 연속으로).
- 반지름·지름·각도 치수 옮기기는 통째로, 손잡이는 두 점(과 꼭짓점). DXF·DWG 로 쓰기는 §43.

## §37 선과 호 모깎기·U자 계단 (2026-11-25)

- 선과 호·원 모깎기: 모깎기 원 중심은 선에서 ±r 떨어진 직선과 원에서 R±r 떨어진 원의 교점 — 후보 중 접점이 누른 두 점에
  가장 가까운 것 (`modify::fillet_line_arc`). 선은 누른 쪽 먼 끝에서 접점까지, 호는 접점에서 나눠 누른 쪽을 남기고
  (접점이 호 밖이면 가까운 끝을 늘림), 원은 그대로 둔다.
- U자 계단: 꺾는 점 뒤로(첫 줄기 쪽) 반 폭 넘게 돌아오고 옆으로 계단 폭 이상 떨어진 끝점이면 U자 (`Stair::u_turn`).
  둘째 줄기는 첫 줄기와 나란히 거꾸로, 참은 두 줄기를 덮는 직사각형. 단 수는 두 줄기 길이 비례.

## §38 단면 자동 (2026-11-25)

`arch::Section`(이름, 자르는 선 a→b, 단면도 자리 at)을 두면 평면에는 자르는 선·보는 쪽 화살표·이름(A, A')을,
모형 공간 at 에는 단면도를 그때그때 만든다 (`section::draw`) — 벽·창·바닥을 고치면 단면도도 바뀐다.
단면도 x 는 자르는 선 a 에서의 거리, y 는 절대 높이. 벽은 자르는 선과 중심선이 만나는 곳에 두께(비스듬하면 두께/|sin|,
너무 비스듬하면 5 배까지)로 칠하고, 그 자리에 문이 있으면 인방 위만, 창이면 창대 아래·인방 위와 유리선. 바닥판은 실 경계와
겹치는 구간에 150, 계단은 줄기가 자르는 선과 나란하고 선이 폭 안을 지나면 계단 모양 선. 층마다 바닥선과
「이름 FL+높이」, 지반선, 제목 「단면 A-A'」. 손잡이: 자르는 선 두 끝·단면도 자리, 옮기기는 단면도 자리.
보이는 선·지붕은 §41. 남은 것: 천장, 보, 단면 해치 종류, 기둥·문짝의 보이는 선.

## §39 IFC 내보내기 (2026-11-25)

`ifc::write` — IFC4 STEP 글. 프로젝트·대지·건물·층(바닥 높이) 아래 벽(두께×길이 직사각형 돌출, 높이), 문·창(벽 두께 상자,
OverallHeight·Width), 실(IfcSpace, 이름·면적 LongName, 층고 돌출), 바닥판(IfcSlab 150), 기둥. 글로벌 ID 는 객체 종류·번호
해시로 늘 같게(다시 내보내도 같은 ID). 한글은 `\X2\…\X0\`. 앱 「내보내기 → IFC」, `dsmith ifc`.
벽 구멍은 §41. 남은 것: 계단, 재료·속성 세트, 가져오기.

## §40 레이어 검사 (2026-11-25)

표 서랍 「레이어 검사」: 레이어 이름이 분야 글자(A·S·M·E·P·C·L·G·F·T·I)-주 그룹(영대문자·숫자 2~6 자)[-부 그룹…] 꼴인지
(KS·AIA CAD 레이어 지침의 꼴), 「0」 레이어에 객체가 있는지. 흔한 이름(벽·WALL·DIM·문자·중심 …)에는 표준 이름을
제안하고, 「제안대로 고치기」 는 그 이름 레이어가 없으면 이름을 바꾸고 있으면 객체를 옮긴다 (한 묶음, 되돌리기 가능).

## §41 IFC 벽 구멍·단면 보이는 선·지붕 (2026-11-25)

- IFC: 문·창마다 벽 두께보다 20 두꺼운 IfcOpeningElement 를 놓고 IfcRelVoidsElement(벽 ← 구멍),
  IfcRelFillsElement(구멍 ← 문·창)로 잇는다 — BIM 프로그램에서 벽에 구멍이 뚫려 보인다.
- 단면도: 자르지 않은 벽 중 두 끝이 모두 보는 쪽(자르는 선 왼쪽)에 있는 것은 자르는 선 위로 투영한 외곽(가는 선,
  `A-SECT-VIEW`)과 그 벽의 창 외곽을 그린다 (가림 처리는 아직 — 앞뒤 벽이 겹쳐 보일 수 있다).
  맨 위층 실 위에는 지붕판(층고 높이, 두께 200)을 자른 단면으로.

## §42 축척별 표현·여러 뷰포트 (2026-11-25)

- 축척별 표현 (`archgen::with_arch_scaled`): 글자·그리드 기호는 축척에 맞춰 종이 위 같은 크기(1:100 에서 2.5 mm),
  1:200 보다 작은 축척(1:200 이상)이면 문 열림 호·창호 기호·실 면적 글자를 빼 단순하게. 시트는 첫 뷰포트 축척으로
  펼친다 (한 시트 안 뷰포트들은 같은 표현). 모형 화면은 1:100 표현.
- 시트에 뷰포트 더하기(옆 칸 ＋ — 틀의 1/3 크기, 왼쪽 아래, 첫 뷰포트와 같은 가운데·축척)·지우기. 되돌리기 한 단계.

## §43 호와 호 모깎기·돌음 계단·배열 블록·치수 소수 자리·반지름/각도 DIMENSION (2026-11-25)

- 호·원 둘 사이 모깎기: 모깎기 원 중심은 두 원에서 각각 R±r 떨어진 원들의 교점 중 접점이 누른 점에 가까운 것
  (`modify::fillet_arcs`). 호는 접점에서 나눠 누른 쪽을 남기고, 원은 그대로.
- 돌음(나선) 계단: `Stair::spiral`(회전각) — a 중심, b 는 중심선 위 시작점. 안·바깥 반지름은 중심선 ± 폭/2, 단은 같은 각으로
  나눈 부채꼴. 평면은 안·바깥 호·단마다 반지름 선·중심선 호 화살표·UP, 3D 는 단마다 부채꼴(네 모서리) 상자.
  계단 도구에서 `S` → 중심 → 시작점 → 회전각(도, 음수면 시계).
- 배열 블록(MINSERT): 가져올 때 칸마다 블록 참조 하나씩 (속성값이 보이는 배열은 펼침 — §46).
- 치수 소수 자리(`precision` 0~4): 속성 칸·치수 스타일에서. 소수 끝 0 은 뺀다(AutoCAD DIMZIN 처럼 3000.00 → 3000).
  가져온 치수는 머리글 DIMDEC.
- 반지름·지름·각도 치수도 DXF·DWG 에 DIMENSION(반지름·지름·3 점 각도)과 모양 블록 *D 로 쓴다.

## §44 최초 버전 검증 (2026-11-25)

결과와 다시 하는 법은 `docs/verification.md`. 검증용 예제 건물(`demo::demo_building`, `dsmith demo`)과 `dsmith export
[--level]` 을 더했다. 외부 도구(ezdxf 감사, IfcOpenShell 스키마·형상)로 확인하다 찾은 결함: 블록 정의 BLOCK·ENDBLK 핸들 0
(고침), 새 시트가 대지·단면도까지 포함한 범위 가운데를 봄(그 층 건물 범위로 — `sheet::building_bbox`), 내보내기가 지금 층만
펼침(파일 이름에 층·CLI `--level`), 건축 객체만 있는 도면의 객체 수 표시.

## §45 무늬 해치 객체·모든 층 내보내기·반지름/각도 치수 가져오기·단면 가림 (2026-11-25)

검증(§44)에서 나온 한계를 고쳤다.
- 무늬 해치: `Shape::Hatch`(경계 고리 + 무늬 선 정의 + 이름). 가져온 무늬 HATCH 와 해치 도구(H)가 만든 무늬는 이 객체로
  남고, 화면·PDF·고르기는 보이는 도면 단계(`archgen::with_arch_owned`)에서 무늬 선분으로 바꿔 쓴다(번호는 그대로).
  내보내기는 모형에서 HATCH(무늬 정의째)로 — DWG→DXF→DWG→DXF 를 돌아도 ANSI31 이 HATCH 로 남는다. 옮기기·회전·
  대칭은 경계와 무늬 기준점·방향·간격·대시를 함께 바꾼다.
- 모든 층 내보내기(`export::all_levels_model`): 층마다 건물 폭 + 10 m 씩 오른쪽에 나란히, 층 이름 제목. 그리드는 층마다
  복사(새 번호)하고 그 층 치수가 묶인 그리드를 바꿔 준다. 대지·단면은 한 번. 앱 「내보내기 → DWG (모든 층 나란히)」,
  CLI `--all-levels`.
- 가져오기: 반지름·지름·3 점 각도·2 선 각도 DIMENSION 도 치수 객체로 (2 선 각도는 두 선 교점이 꼭짓점, 각 선에서 먼 끝이
  반직선 위 점, 호 점까지 거리가 호 반지름).
- 단면 가림: 자른 면과 보이는 벽을 「t 구간 × 높이」 가림막으로 모아, 보이는 벽을 가까운 것부터 그리며 높이를 다 덮는
  앞 가림막의 t 구간을 뺀다(위·아래 변은 남은 구간만, 세로 변은 끝이 보일 때만). 창 외곽도 같은 가림막으로 자른다.
  높이를 일부만 덮는 것(문·창 자리)은 가리지 않는다 — 열린 곳 너머가 보인다.

## §46 단면의 기둥·계단 입면, 속성(ATTRIB) 블록 (2026-11-25)

- 단면 기둥: 자르는 선이 기둥을 지나면 자른 면(굵은 선·무늬), 보는 쪽에 있으면 보이는 외곽(층 바닥~층고)을 그리고 그
  뒤를 가린다(§45 가림막에 더함).
- 단면 계단: 자르는 선과 나란한 계단 줄기가 보는 쪽에 있으면 단마다 디딤판·챌판 계단 모양 입면으로. 앞 가림막에 완전히
  가려진 줄기는 그리지 않는다.
- 속성 블록: `Shape::Insert::attrs`(태그 + 글자). 글자는 블록 안 좌표로 두어 참조를 옮기고 돌리고 대칭해도 함께 간다.
  화면·PDF 는 펼칠 때(`block::expand`) 참조의 레이어·색으로 그리고, 펼치기(X)하면 보통 글자가 된다.
  - 가져오기: 보이는 ATTRIB 가 있는 참조도 블록 참조로 살리고 ATTRIB(세계 좌표)을 참조의 역변환(`Affine::inverse`)으로
    블록 안 좌표로 바꾼다. 속성값이 있는 배열 블록(MINSERT)은 속성이 첫 칸에만 붙으므로 펼친다.
  - 내보내기: INSERT 에 ATTRIB(세계 좌표·맞춤) — ezdxf 감사 오류 0.
  - 앱: 블록 참조 하나를 고르면 속성 칸에 「속성 태그」 값 칸(바로 고침)과 「속성 더하기…」(태그·값·글자 높이, 블록 아래로
    줄지어 놓임). 태그는 대문자, 빈칸 없이, 참조 안에서 하나씩.
  - 블록 정의 쪽 ATTDEF(기본값·묻는 말)는 아직 없다 — 참조마다 속성을 붙인다.

## §47 IFC 가져오기 (2026-11-25)

`ifc_read::read` — IFC2x3·IFC4 STEP 파일을 외부 라이브러리 없이 읽어 건축 객체로(`.ifc` 를 열기·끌어 놓기·CLI `info`).
평면 CAD 라서 3D 를 다 풀지 않고, 객체의 놓인 자리(IfcLocalPlacement 사슬, Z 는 위로 봄)와 몸체의 바닥 모양(밀어 올린
단면 — 사각형·다각형·원, 잘라 낸 몸체는 첫 몸체, 대응 항목은 원점까지)만 읽는다.
- 길이 단위: IfcSIUnit 접두어(MILLI·CENTI·없음=m) 또는 FOOT·INCH 를 mm 로.
- 층: IfcBuildingStorey(높이 순), 층고는 다음 층까지(마지막은 앞 층고, 하나면 3000).
- 소속: IfcRelContainedInSpatialStructure·IfcRelAggregates 를 위로 따라가 층을 찾고, 없으면 높이가 가까운 아래층.
- 벽(IfcWall·StandardCase·ElementedCase·CurtainWall): 'Axis' 표현이 있으면 그 두 끝 + 바닥 모양을 축에 수직으로 잰 폭이
  두께, 없으면 바닥 모양을 가장 긴 변에 맞춘 상자의 긴 쪽 중심선·짧은 쪽 두께. 이름에 「내벽」·interior 가 있거나 두께
  150 mm 미만이면 내벽. 한쪽 면 기준으로 그린 벽(IfcOpenShell·Revit 등)은 중심선 끝이 닿지 않으므로, 같은 층 두 벽의
  중심선 교점에서 두 두께 안에 있는 끝을 교점으로 옮긴다(`join_corners`) — 평면 생성이 L·T 맞댐으로 잇는다.
- 문·창: IfcRelFillsElement → 구멍 → IfcRelVoidsElement → 벽. 자기 몸체(없으면 구멍 몸체)를 벽 축에 내린 구간의 가운데가
  위치, OverallWidth·Height(없으면 몸체 크기), 창대는 놓인 높이 − 층 높이. 다른 프로그램마다 문 원점이 가운데·끝으로
  다르므로 원점을 쓰지 않는다.
- 실: 바닥 다각형, 이름은 LongName(없거나 우리가 쓴 「… m2」 면 Name).
- 기둥: 바닥 모양 상자. 원기둥은 지름 정사각 (사각 기둥만 있으므로).
- 그리드: IfcGrid 의 IfcGridAxis 선과 이름.
- 계단·슬래브·지붕은 읽지 않는다(바닥판은 실에서 다시 만든다). B-rep·면 모델만 있는 객체는 건너뛴다.
- 시험: 우리 IFC 왕복(예제 건물 — 벽 끝·두께·문 위치·실 면적·층 소속이 같음), IfcOpenShell API 로 만든 파일
  (`crates/draftsmith-core/testdata/`, 한쪽 면 기준 벽·끝 원점 문·원기둥), 미터 단위 + 축선 없는 벽.
