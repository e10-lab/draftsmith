# 구현 노트

결정과 근거를 번호(§)로 남긴다. 코드 주석은 이 번호를 가리킨다.

## §1 개발 환경을 BEATS 와 같게 (2026-11-24)

Rust 작업공간에 코어·CLI·앱 세 crate. 앱은 Tauri 2, 화면은 HTML·CSS·순수 JS 모듈(npm·번들러 없음).
`cargo build/test` 기본 대상은 코어·CLI 이고 앱은 `-p draftsmith-app`.
검토했다가 접은 것: 네이티브 화면 위에 투명 웹 UI 겹치기, Rust 네이티브 UI(egui·iced·Slint), Qt, GPUI —
한글 입력 안정성과 개발 부담 때문 (결정 과정은 ROADMAP 2026-11-24 판 이전 논의).

## §2 판 표시

판은 `Cargo.toml` 한 곳. `build/version.rs` 가 git 상태를 보고 「0.1.0」·「0.1.0-dev (커밋)」·「…*」 를
`DRAFTSMITH_VERSION` 으로 넘긴다 (BEATS 구현 노트 §218 과 같은 방식).

## §3 DXF·DWG 는 acadrust

순수 Rust, MPL-2.0, R12~R2018 읽기·쓰기. DWG 코드는 ACadSharp(MIT)에서 옮긴 것이라 GPL 코드가 없다
(`THIRD_PARTY_NOTICES.md` 확인). 2007 이전 도면의 `ANSI_949`·조합형을 `encoding_rs` 로 푼다 (소스 확인).
DWG 여부는 파일 머리 `AC` + 숫자로 본다.

지금 가져오는 것: LINE, LWPOLYLINE, POLYLINE(2D), CIRCLE, ARC, TEXT, MTEXT(위치·크기만).
그 밖(INSERT·HATCH·DIMENSION 등)은 `Drawing::skipped` 에 개수를 남겨 화면·CLI 에 알린다 — 실무 도면은
블록이 많으므로 INSERT 펼치기가 M0 ② 의 첫 일이다.

## §4 화면에는 바이너리 표시 데이터

열린 도면은 앱(Rust)이 들고, 화면에는 `display_data` 명령이 선분 목록 바이너리(`DSD1`)를
`tauri::ipc::Response` 로 넘긴다. 형식은 `draftsmith_core::display` 머리 주석.

- 좌표는 도면 범위 중심(origin)을 뺀 f32 — GPU f32 정밀도 문제(TM 좌표) 회피.
- 원호는 화살 높이가 도면 대각선의 1/20000 이하가 되게 8–512 조각.
- 문자는 글꼴 처리 전이라 밑줄로 자리만 (M0 ⑥).

첫 측정 (2026-11-24, 클라우드 개발 컨테이너, 4 코어):
`dsmith sample 100000` (선 4 만·원 4 만·폴리선 1 만·한글 문자 1 만, DXF 16.6 MB) →
읽기 358 ms, 선분 41 만 개 펼치기 14 ms, 바이너리 3 ms (8.2 MB).
화면(Chromium, 소프트웨어 WebGL)에 올리기 18 ms. 실제 WKWebView·WebView2 와 Tauri 전달 시간은 실기 측정이 남았다.

## §5 블록 참조(INSERT) 펼치기 (2026-11-24)

**고친 오류**: acadrust 의 `entities()` 는 블록 정의 안 객체까지 모두 돌려준다. 처음 골격은 이것을 그대로 써서
블록 안 모양이 원점 근처에 한 번 더 그려졌다. 이제 `model_space_entities()` 에서 시작하고, 블록 안 객체는
`entities_in_block(이름)` 으로 참조마다 펼친다.

변환 순서 (블록 안 좌표에서 바깥으로):
`−기준점 → 축척(x, y) → 회전 → 삽입점(배열이면 칸마다) → 돌출 방향(OCS) → 바깥 블록의 변환`.

- **돌출 방향 −Z**: 대칭 복사한 블록·원·폴리선에 흔하다. X 를 뒤집는 변환으로 처리한다. 기울어진 돌출 방향은 무시.
- **원·호**: 회전·균등 축척이면 원·호 그대로, 대칭이 들면 원은 원·호는 시작·끝 각을 `β − 끝, β − 시작` 으로
  (β = 변환 뒤 x 축 방향). 비균등 축척이면 타원(켤레 반지름 u·v 꼴)으로 바꾼다 — 아무 아핀 변환에도 닫혀 있다.
- **폴리선 불지**: 등각이면 그대로, 대칭이면 부호만 뒤집고, 비균등 축척이면 호를 32 조각으로 펼친 뒤 변환.
- **문자**: 높이는 글자 위쪽 방향이 늘어난 만큼, 방향은 진행 방향이 돈 만큼.
- **레이어·색 물려받기**: 블록 안 「0」 레이어 객체는 참조의 레이어로, ByBlock 색은 참조의 색으로.
- **속성값(ATTRIB)**: 이미 세계 좌표라 바깥 변환만 건다. 숨김 속성은 뺀다.
- **안전장치**: 블록 안 블록 깊이 16, 자기 자신을 부르는 정의는 건너뛰고 `skipped` 에 「블록 순환·깊이 초과」.
  펼친 객체가 2 천만 개를 넘으면 멈춘다. acadrust 가 너무 큰 배열을 거부하면 「배열 블록 한도 초과」.
- 가져오지 않은 객체 이름은 acadrust 의 `entity_type()` (Debug 출력 대신 — 빠름).

측정용 도면에 문 블록(「문-900」, 한글 블록 이름, 칸마다 번갈아 대칭)을 넣었다.
DXF·DWG 왕복 모두 펼친 결과가 메모리에서 바로 펼친 것과 개수·범위가 같다 (시험 `grid_round_trips_through_*`).

측정 (11 만 객체, 블록 참조 1 만 개 펼침): DXF 17.3 MB 읽기 544 ms / DWG 2.1 MB 읽기 239 ms,
선분 42 만 개 펼치기 14–18 ms.

## §6 해치·치수·솔리드·스플라인·문자 (2026-11-24)

- **해치**: 경계(선·원호·타원호·스플라인·불지 폴리선 변)를 고리로 펼친다. 시계 방향 원호 변은 각도가
  거울상으로 저장되므로 `−시작 → −끝` 시계 방향으로 그린다. 솔리드·그러데이션이면 채움(`Shape::Fill`),
  무늬면 무늬 선(`Shape::Segments`). 무늬 선은 DXF 에 저장된 값(축척·각도 적용됨)으로 만들고 짝홀 규칙으로
  경계 안만 남긴다 (경계 위 선은 반열림 규칙). 한 해치에 20 만 선분을 넘으면 무늬 대신 경계선만 그리고 알린다.
- **채움 삼각형**: 고리마다 다른 고리에 몇 번 싸였는지(깊이)로 바깥·구멍을 나누고 earcut 으로 분할 (짝홀 규칙).
- **치수**: 치수가 그려 둔 익명 블록(`*D…`)을 펼친다 (치수 문자·화살표 SOLID 포함). 블록이 없는 파일이면
  선형·평행 치수만 간단히 그린다 (치수선·보조선·45° 사선·측정값, 글자 높이는 길이의 1/20).
- **SOLID**: 꼭짓점 순서 1-2-4-3 으로 채움.
- **스플라인**: NURBS de Boor (가중치 포함), 매듭 구간마다 16 조각. 조정점이 없으면 맞춤점을 잇는다.
- **문자**: TEXT 맞춤(가로 왼·가운데·오른, 세로 바탕선·아래·가운데·위)과 맞춤점, MTEXT 붙는 점 1–9,
  폭 배율. MTEXT 서식 코드(`\P` 줄바꿈, `\f…;` 글꼴, `\H…;` 크기, `\S…;` 쌓기, `\U+XXXX` 등)와 `%%c/%%d/%%p`
  를 걷어 내고 보이는 글자만 남긴다. 대칭한 블록 안 문자는 뒤집지 않고 읽을 수 있게 둔다 (MIRRTEXT=0).
- **화면**: 선·채움은 WebGL2 (`DSD2` 형식에 삼각형 추가), 문자는 그 위 Canvas 2D 층에 글꼴로 (`DST1` 형식,
  `text_data` 명령). 3 화면 점보다 작은 글자와 화면 밖 글자는 그리지 않는다. 글꼴 크기 = 도면 글자 높이 × 1.35
  (도면 글자 높이는 대문자·한글 높이). 공개 글꼴 내장은 다음 일 — 지금은 OS 한글 글꼴.

### 실제 앱 실행 확인 (Linux, 가상 화면)

앱을 `draftsmith-app 도면.dwg` 처럼 경로를 넘겨 실행하면 바로 연다 (`startup_file` 명령 — 파일 연결에도 쓴다).
처음 실행에서 Linux(WebKitGTK)는 Tauri 바이너리 응답이 ArrayBuffer 가 아니라 숫자 배열로 와서 그리지 못했다.
화면에서 ArrayBuffer·Uint8Array·숫자 배열을 모두 받게 고치고, 숫자 배열(JSON 대체 경로)이면 상태 막대에
「느린 경로」 라고 띄운다. macOS·Windows 에서 빠른 경로인지 이것으로 확인한다.

측정용 도면 10 만 (펼치면 15 만 객체, 블록 8 천, 해치 8 천, 치수 8 천):
CLI 읽기 425 ms · 선분 41 만 펼치기 26 ms. 앱(Linux, 느린 경로): 읽기 445 ms · 전달 663 ms (9.6 MB) · 올리기 71 ms.

## §7 스냅·측정·내장 글꼴·최근 파일 (2026-11-24)

- **스냅 색인** (`draftsmith_core::snap`): 켜진 레이어 객체의 끝점·중간점(불지 호는 호 가운데)·중심·사분점·
  문자 삽입점, 솔리드 꼭짓점을 R*-tree(rstar)에 넣는다. 해치 무늬 선은 너무 많아 뺀다. 도면을 열 때와
  레이어를 켜고 끌 때 다시 만든다. 커서에서 가장 가까운 점이 화면 12 점 안이면 붙는다 (종류 우선순위 없음).
- **M0 ⑤ 스냅 계산 위치**: 마우스가 움직일 때마다 Rust `snap` 명령을 부르고, 한 번에 하나만 보내며 밀린 것은
  마지막 위치만 보낸다. 지연 중앙값을 커서 좌표 옆에 보인다. Linux(느린 경로)에서 약 9 ms — 쓸 만하다.
  macOS·Windows 실측 후 결정한다 (화면 쪽으로 옮길지).
- **측정 도구** (`ui/js/measure.js`, 단축키 D): 두 점 → 거리·ΔX·ΔY·각도. 끌기는 화면 이동, 제자리 누르기만 도구 클릭.
- **단축키는 자판 위치(`e.code`)로** — 한글 입력기가 켜져 있어도 같은 자리에서 동작. 조합 중이면 무시.
- **내장 글꼴**: Pretendard 1.3.9 Regular·SemiBold woff2 (npm `pretendard`, SIL OFL 1.1, `ui/fonts/` 에 라이선스).
  화면과 도면 문자 모두 이것을 먼저 쓴다. 글꼴을 읽은 뒤 문자를 다시 그린다.
- **최근 파일**: 앱 설정 폴더 `recent.txt` (최대 12 개, 없는 파일은 목록에서 뺌). **끌어 놓기**로 열기.
- 레이어 목록은 쓰는 객체가 없는 레이어를 숨긴다.

### 실제 앱 조작 확인 (Linux 가상 화면, xdotool)

D → 기둥 원 근처 누르기 → 다음 칸 기둥 근처 누르기: 스냅 표시(사분점 ◇)·점선 측정선·길이 표지가 그려지고
상태 막대에 「거리 5,850.0 · ΔX 5,850.0 · ΔY 0.0 · 각도 0.0°」.

## §8 고르기·속성 (2026-11-24)

- **고르기 색인** (`draftsmith_core::pick`): 켜진 레이어 객체의 경계 상자를 R*-tree 에 넣어 후보를 줄이고,
  후보는 실제 모양까지의 거리로 고른다 (화면 6 점 안). 채움은 안쪽을 눌러도, 문자는 글자 상자 안을 눌러도 고른다.
  같은 거리면 나중에 그린(위에 있는) 객체.
- **속성**: 종류·레이어·색(레이어 색인지)·길이·각도·점 좌표·반지름·둘레·호 길이·꼭짓점 수·면적·문자 내용·높이.
  면적은 도면 단위(`$INSUNITS`)로 ㎡·평도 함께 (1 평 = 3.305785 ㎡). 단위가 없으면 국내 관례대로 mm 로 보고 밝힌다.
- **강조 표시**: 고른 객체의 외곽 선분을 도구 층에 굵게 (최대 2 만 선분).
- 기본 도구가 고르기, D 로 측정, Esc 는 측정 끝·고르기 풀기. 도면을 열거나 레이어를 바꾸면 고르기를 푼다.
- 치수는 펼친 조각(선·문자·화살표)이 따로 골라진다 — 치수 하나로 묶는 것은 편집(M2) 때 객체 모델과 함께.

## §9 선 종류 (2026-11-24)

- 선 종류 표의 무늬(대시 길이: 양수 선, 음수 빈칸, 0 점)를 읽는다. 빈칸이 없는 것(CONTINUOUS 등)은 실선.
  복합 선 종류의 글자·모양 요소는 아직 그리지 않고 길이만 따른다.
- 객체 선 종류: 비었거나 ByLayer 면 레이어 선 종류, ByBlock 이면 블록 참조의 것, 아니면 이름으로.
- 무늬 배율 = 전역 LTSCALE × 객체 배율 × 블록 축척 (블록 안 객체는 블록과 함께 커진다).
- 그리기: 선·원·호·타원은 한 조각, 폴리선은 꼭짓점마다 무늬를 새로 시작 (AutoCAD PLINEGEN 끔과 같음).
  한 조각에 무늬가 2 천 번을 넘거나 무늬가 허용 오차보다 작으면 실선으로 (화면에서 어차피 실선처럼 보임).
- 채움·해치 무늬·문자에는 선 종류를 걸지 않는다.
- 측정용 도면에 CENTER 선 종류 레이어(A-GRID)와 칸마다 중심선을 넣었다 — DXF·DWG 왕복 시험 통과.

## §10 PDF 출력 (2026-11-24)

- `draftsmith_core::pdf` (krilla 0.8, MIT/Apache). 선·채움은 화면용 표시 데이터(`display::segments`)를 그대로
  써서 선 종류·곡선 펼치기가 화면과 같다. 색마다 경로 하나로 묶어 파일이 작다 (작은 평면 8 KB).
- 문자는 내장 Pretendard Regular(OTF, `crates/draftsmith-core/fonts/`, OFL)를 **부분 삽입** — 쓴 글자만 들어가
  한글이어도 작다. 가로 맞춤용 글자 폭은 ttf-parser 로 글꼴 advance 를 더한다. 글꼴 크기·줄 간격·세로 맞춤은
  화면과 같은 규칙 (글자 높이 × 1.35, 5/3).
- 설정: 용지 A4–A0·방향, 축척(1:N, 도면 단위 mm 기준 — `$INSUNITS` 로 환산) 또는 용지에 맞춤, 범위(도면 전체·
  지금 화면 — 범위 밖은 잘라냄), 컬러/흑백, 선 굵기 0.18 mm. 범위는 용지 가운데에.
- 종이 색 규칙: 흰색 → 검정, 밝은 색은 어둡게 (화면 흰 배경과 같음). 흑백이면 선·글자·채움 모두 검정
  (AutoCAD monochrome.ctb 와 같음 — 처음엔 채움을 회색으로 했으나 치수 화살표까지 회색이 되어 바꿈).
- 앱: 「PDF」(⌘P / Ctrl+P) 설정 칸 → 저장 대화상자. CLI: `dsmith pdf 도면 출력.pdf --paper A3 --scale 100 --mono`.
- Rust MSRV 를 krilla 에 맞춰 1.92 로.

### 함께 고친 것
- 설정 칸이 닫히지 않던 것: 작성자 CSS 의 `display: grid` 가 `hidden` 을 덮었다 → `[hidden] { display: none !important }`.
- 흰 배경 설정이 앱을 다시 열면 사라지던 것 (WebKitGTK localStorage): 앱 설정 폴더 `settings.txt` 에
  `이름=값` 으로 저장하는 `get_setting`/`set_setting` 명령으로 바꿨다 (최근 파일과 같은 곳).

## §11 선 굵기 (2026-11-24)

- 객체 선 굵기: ByLayer 면 레이어 굵기, ByBlock 이면 블록 참조의 것, Default 면 없음, 값이면 그 값 (1/100 mm).
  블록 안 「0」 레이어 객체는 참조의 레이어를 받으므로 그 레이어 굵기를 쓴다 (치수 블록 안 선이 치수 레이어 굵기로).
- 표시 데이터 `Segments.weights` 에 선분마다 굵기를 담는다 (바이너리에는 넣지 않음 — 화면은 아직 1 화면 점).
- PDF: (색, 굵기) 마다 경로 하나. 굵기가 없으면 출력 기본 굵기(0.18 mm), 있으면 그 값(최소 0.05 mm).
- 색 기준 펜 굵기(CTB 출력 스타일)는 M4 에서.

## §13 배치(종이 공간)·뷰포트 (2026-11-24)

- 읽기: 배치 객체(Layout)마다 블록 기록(`*Paper_Space…`)의 객체를 펼쳐 종이 객체로, VIEWPORT 는 뷰포트로 모은다.
  모형(Model) 배치와 빈 배치는 뺀다. 탭 순서로 정렬.
- 종이 전체 뷰포트(번호 1)는 뺀다. **DWG 는 뷰포트 번호를 저장하지 않아** 읽을 때 순서대로 번호가 붙는데,
  AutoCAD 는 이것을 늘 배치의 첫 뷰포트로 두므로 같은 규칙이 맞는다. 다른 프로그램이 종이 전체 뷰포트 없이 쓴 DWG 는
  첫 뷰포트가 빠질 수 있다 (측정용 도면도 처음엔 그래서 DWG 왕복에서 뷰포트가 사라졌다 → 종이 전체 뷰포트를 먼저 넣음).
- 꺼진 뷰포트, 3D 방향 뷰포트(보는 방향이 +Z 가 아님)는 뺀다 (3D 는 알림). 비사각 자르기 경계는 아직 사각형으로.
- 모형 → 종이 변환: `−대상점 → 비틀기(−각) → −보는 가운데 → ×(높이/보는 높이) → +종이 가운데`. 비틀기 부호는 실제
  비튼 도면으로 확인이 남았다.
- 합치기(`layout::compose`): 뷰포트마다 모형 객체를 변환해 뷰포트 사각형에 다 들어가면 그대로, 다 밖이면 버리고,
  걸치면 선은 Liang–Barsky 로 잘라 선분 묶음, 채움은 Sutherland–Hodgman 으로 자른 고리, 문자는 기준점이 안이면 둔다.
  뷰포트에서 얼린 레이어는 뺀다. 결과는 종이 좌표(mm) 의 보통 도면이라 화면·고르기·스냅·PDF 가 그대로 쓴다.
  뷰포트를 먼저, 종이 객체를 나중에 쌓는다.
- 앱: 도면 아래 「모형 | 배치…」 탭. 배치를 고르면 PDF 축척이 1:1 로 바뀐다. CLI: `dsmith pdf … --layout 이름 --scale 1`,
  `dsmith info` 에 배치 목록.
- PDF 는 범위를 정했을 때만 잘라낸다 (도면 전체를 자르면 경계 위 도곽선이 반쯤 잘려 안 보였다), 자를 때는 1 mm 여유.

## §14 복구 읽기·옛 DXF 한글 (2026-11-24)

  처음 오류를 알린다. (잘린 DXF 는 복구도 실패 — 정상. 값 하나가 깨진 DXF 는 acadrust 가 엄격 모드에서도 넘어갔다.)

## §15 화면 선 굵기 보기 (2026-11-24)

- 표시 데이터 형식을 `DSD3` 으로: 끝에 선분마다 굵기(u8, 1/100 mm, 0 = 기본)를 붙였다.
- 화면: 「선 굵기」(W) 를 켜면 선분마다 사각형(삼각형 2 개)을 GPU 인스턴싱으로 그린다 — 인스턴스 하나가 선분 하나,
  꼭짓점 셰이더가 `gl_VertexID` 로 모서리를 정한다. 끄면 예전처럼 1 화면 점 `LINES` (가볍다).
- 두께는 확대와 무관하게 굵기(mm) × 4 화면 점, 최소 1 점 (AutoCAD LWT 처럼 화면 점 고정). 기본 굵기는 0.25 mm 로 본다.
  꺾인 곳 틈이 보이지 않게 선분 끝을 반 굵기만큼 늘린다.
- 설정은 앱 설정 폴더에 기억 (`lwt`).

## §16 색 기준 출력 스타일 (CTB) (2026-11-24)

- 객체마다 색 번호(ACI)를 풀어 둔다 (`Entity::aci`): 색 번호면 그것, ByLayer 면 레이어 색 번호, ByBlock 이면 블록 참조의
  것. 트루컬러는 없음. 표시 데이터 `Segments` 에 선분·삼각형마다 색 번호를 담는다 (바이너리에는 넣지 않음).
- `.ctb` 읽기 (`draftsmith_core::ctb`): 머리 60 바이트 뒤 zlib → 글. `plot_style{ 번호{ color= lineweight= screen=
  color_policy= } }`, `lineweight{ 번호=mm }`. 번호 0 이 색 1. 색 값 −1·−1006632961 은 「객체 색」, 굵기 번호 255 는
  「객체 굵기」. color_policy 의 2 비트는 회색조, screen 은 농도(흰색 쪽으로 섞음).
- PDF: 출력 스타일이 있으면 색 번호마다 펜 색·굵기가 앞선다 (펜 굵기 → 객체 굵기 → 기본 0.18 mm). 펜이 「객체 색」 이면
  흰색(색 7)만 검정으로. 흑백 선택이 가장 우선.
- 앱: PDF 설정 칸 「출력 스타일」 에서 CTB 파일을 고르면 기억한다 (`ctb` 설정). CLI: `dsmith pdf … --ctb 파일.ctb`.
- 시험: 글로 만든 CTB(zlib) 로 펜 해석·적용 확인. **실제 AutoCAD CTB 파일로는 아직 확인하지 못했다** — 사무소 CTB 로 확인 필요.

## §17 DraftSmith 파일 `.dsmith` (2026-11-24)

## §19 건축 객체 → 평면 선 (2026-11-24)

`arch::ArchModel` 에 층·벽·개구부(문·창)·실·그리드·대지를 저장하고, 평면 선은 저장하지 않고 그때그때 만든다
(`archgen::with_arch`). 그래서 벽 두께를 고치면 문·창·실·해치가 함께 따라온다. 만드는 규칙:
- 벽: 중심선 ± 두께/2. 끝이 다른 벽 끝과 만나면 L 자 맞댐(두 면 연장선 교점), 다른 벽 몸통에 닿으면 T 자(그 벽 면에서 자름).
  단면 해치는 `A-WALL-PATT` 에 칠.
- 문: 벽을 끊고 문짝 선과 90° 여는 호(`A-DOOR`), 창: 벽을 끊고 유리선 두 줄(`A-GLAZ`). 기호(D1, W1 …)는 폭·높이가
  같은 것끼리 같은 번호.
- 실: 경계 다각형(`A-AREA`), 가운데에 이름과 면적 ㎡·평(`A-AREA-IDEN`). 「실」 도구는 누른 점에서 720 방향으로
  반직선을 쏴 처음 닿는 벽 안쪽 면으로 경계를 만든다 (직교 평면에서 맞는 단순한 방법 — 사선·곡면 벽은 나중에).
- 그리드: 1 점 쇄선(`A-GRID`)과 양 끝 기호 원(`A-GRID-IDEN`). 그리드 세트는 간격 목록으로 X·Y 를 한 번에.
- 고르기: 만든 선마다 주인(종류, 번호)을 기억해 누르면 그 건축 객체를 고르고, 속성 중 「:고침」 붙은 값은 바로 고친다.
- 건축 객체 편집은 모델 전체를 `Op::Arch{old,new}` 로 남긴다 (모델이 작아 이것이 단순하고 안전).
- 표(§22)와 3D(§24)도 같은 모델에서 나온다.

## §25 작도 화면 (2026-11-24)

- 명령줄이 늘 초점을 가진다: 도면을 눌러도 곧바로 칠 수 있다. 명령은 AutoCAD 단축(L·PL·M·CO …)과 한글 이름(선·이동 …)
  둘 다, ⌘K 팔레트는 이름·단축·초성(ㄱㄸ → 간격띄우기)으로 찾는다. 빈 Enter·Space·오른쪽 누르기는 「마치기」, 도구가
  없으면 지난 명령 되풀이 (AutoCAD 와 같음). 글을 받는 단계(글자·실 이름·그리드 기호)에서는 Space 가 그냥 띄어쓰기.
- 점 입력: 누르기(스냅·직교 적용) 또는 `x,y`·`@dx,dy`·`@거리<각`·`거리`(커서 쪽으로).
- 스냅은 끝점·중간점·중심·사분점·삽입점(F3), 직교는 F8 또는 Shift 누른 동안.
- 고르기: 누르기(Shift 더하기·빼기), 왼→오른 끌기는 창(안에 다 든 것), 오른→왼은 걸침. 화면 이동은 가운데 버튼·
  Space+끌기·트랙패드. 수정 도구는 고른 것이 없으면 먼저 고르게 한다.
- 편집은 모두 Rust `edit` 명령 하나 → 돌아온 상태(DocState)로 옆 칸을 다시 그린다. 표시 데이터 기준점이 바뀌어도
  보던 화면이 움직이지 않게 기준점 차이만큼 보정한다.
- 저장 안 한 변경이 있으면 새 도면·열기·창 닫기 전에 묻는다 (rfd 대화상자 — 창 닫기는 Rust 창 이벤트에서).

## §26 치수·글자 (2026-11-24)

(치수는 §28 에서 치수 객체로 바뀌었다.) 치수·글자 크기는 글자 높이(기본 250 = 1:100 에서 2.5 mm)에 비례.
글자 도구는 명령줄로 받아 한글 입력기가 그대로 동작하고, Enter 마다 다음 줄로 이어 쓴다.

## §27 자르기·연장·모깎기·해치 (2026-11-24)

`modify` — 선·호·원·폴리선(불지 포함)을 조각(선분·호) 열로 보고, 조각 k 의 매개변수 t 를 이어 붙인 전체 매개변수
위에서 처리한다. 경계는 화면에 보이는 모든 객체(건축 객체가 만든 벽선 포함) — AutoCAD 「빠른 자르기」 와 같다.
- 자르기: 누른 점에서 가장 가까운 매개변수를 찾고, 그 양옆 교점 사이를 없앤다. 열린 것은 0~2 토막, 닫힌 것(원·닫힌
  폴리선)은 교점이 둘 이상일 때 한 토막(원은 호)으로.
- 연장: 누른 점에 가까운 끝 조각을 무한 직선·온전한 원으로 늘려, 끝 너머 가장 가까운 교점까지.
- 모깎기: 지금은 선 두 개. 두 직선 교점에서 고른 쪽 방향으로 접점 거리 r / tan(φ/2), 반지름 0 이면 모서리.
- 해치: 누른 점을 품은 가장 작은 닫힌 폴리선·원, 없으면 점에서 720 방향 반직선이 처음 닿는 선들로 경계를 만든다
  (실 찾기와 같은 단순한 방법). 무늬는 SOLID·사선·격자·콘크리트, 간격은 도면 단위.
- 편집은 `Editor::reshape` — 바꾸기·더하기·지우기를 한 묶음 작업으로 (되돌리기 한 단계).
- 건축 객체가 만든 선은 자르지 않는다 (속성으로 고친다).

## §28 치수 객체 (2026-11-24)

치수는 건축 모델의 `Dim`(두 점, 치수선까지 거리, 글자 높이, 글자 바꾸기) — 평면 선처럼 그때그때 펼친다.
값은 늘 두 점 길이에서 새로 세어 쉼표를 넣고(12,000), 「글자」 칸에 `<>` 를 쓰면 그 자리에 길이가 들어간다.
옮기기·지우기·속성 고치기는 다른 건축 객체와 같다. 층에 속해 층별 시트에 그 층 치수만 나온다.
끝점이 그리드 선·기둥·벽 위면 그 객체에 묶는다(`Anchor` — 객체 좌표계의 앞·왼쪽 거리). 한 점이 여럿에 걸리면
그리드 > 기둥 > 벽, 같은 종류면 치수 방향과 가장 직각인 것 (가로 치수 끝은 세로 그리드 — 교점에서도 맞게).
묶인 객체를 옮기면 치수 값이 따라 바뀐다. 치수를 옮기면 치수선만 옮긴다(끝점은 묶인 객체를 따름).
연속 치수: 치수 하나를 넣은 뒤 다음 점만 누르면 같은 치수선으로 이어 간다 (N 새 치수, Enter 끝).
내보낼 때는 DIMENSION 으로 (§31). 남은 것: 모형 선(벽이 아닌 객체)에 묶기, 누적 치수.

## §29 기둥·계단·도면 목록 (2026-11-24)

- 기둥: 사각(폭·깊이·회전), 평면은 외곽선(`A-COLS`) + 칠(`A-COLS-PATT`), 3D 는 층고만큼.
- 계단: 곧은 계단 a→b, 폭·단 수. 평면은 외곽·디딤판 선·오름 화살표·「UP」(`A-STRS`), 속성에 단 높이(층고/단 수)·
  디딤판 깊이, 3D 는 단마다 상자. 꺾인 계단·끊김선·법규(단 높이 ≤ 200 등) 검토는 남음.
- 층 복사는 기둥·계단도 함께. 층을 지우면 그 층 치수·기둥·계단도 지운다.
- 표 서랍에 「도면 목록」(배치 순서, 「번호 도면명」 이름을 나눠 번호·도면명, 시트의 층).

## §30 블록 (2026-11-24)

`Drawing::blocks` 에 블록 정의(이름, 기준점 원점 객체들), 도면에는 `Shape::Insert`(이름·삽입점·x·y 배율·회전) 한 객체.
화면·PDF·시트·내보내기에는 `archgen::with_arch` 가 펼친 객체를 덧붙인다 (건축 객체 선과 같은 길, 주인 ("block", 참조 번호)).
그래서 펼친 선을 누르거나 상자로 고르면 참조 하나가 골라지고, 이동·회전·대칭·복사는 참조에 건다. 참조의 대칭은
y 배율을 뒤집고 각도를 거울 쪽으로 (M·R(θ)·S = R(2α−θ)·S(sx, −sy)). 블록 안 레이어 「0」 객체는 참조 레이어·색을 따르고,
블록 안 블록은 8 단까지. 만들기(B)는 블록 정의 추가·고른 객체 지우기·참조 넣기를 한 작업으로 (되돌리기 한 단계),
펼치기(X)는 참조를 안의 객체로 바꾼다. 가져오기·내보내기는 §31.

## §31 블록·치수 가져오기·내보내기 (2026-11-24)

- 내보내기(`export::to_document`)는 이제 모형 도면을 받는다. 블록 정의는 BLOCK, 참조는 INSERT(배율·회전 그대로),
  치수 객체는 DIMENSION(정렬 — 정의점 두 개, 치수선 점, 측정값, 글자 바꾸기는 user text 로 `<>` 그대로) 과
  그 모양(선·눈금·글자)을 담은 익명 블록 `*D1…` 로 — AutoCAD 등은 치수로 고르고, 블록을 그대로 그린다.
  그 밖의 건축 객체 선은 펼친 선으로.
- 가져오기는 모형 공간의 블록 참조 중 단순한 것(배열 아님, 평면 +Z, 보이는 속성값 없음)을 `Shape::Insert` 로 살린다.
  정의는 처음 만날 때 기준점이 원점이 되게 펼쳐 담고(안의 블록은 펼친 채), 레이어 「0」·ByBlock 색은 참조를 따른다
  (ByBlock 선 종류·굵기는 아직 잃는다). 나머지(배열·속성값·기울어진 참조)는 지금처럼 펼친다.
- 다시 읽으면 블록은 블록으로, 치수는 치수 객체로 돌아온다 (§32).
- 블록을 모르는 곳(CLI 보기·PDF·측정)은 `archgen::with_arch` 나 `block::flatten` 으로 펼쳐서 쓴다.

## §32 치수 가져오기·회전 치수 (2026-11-24)

- 치수 객체에 `rotation`(회전 치수 방향 — 가로 0, 세로 π/2. 없으면 정렬 치수)과 `layer` 를 더했다. 회전 치수는 두 점을
  그 방향에 내린 길이를 재고, 치수선은 a 에서 왼쪽(n)으로 offset 인 직선. 모양 계산은 `Dim::geom` 한 곳에서
  (평면 선·속성·옮기기·내보내기가 함께 쓴다).
- 가져오기: 모형 공간의 선형(회전)·정렬 DIMENSION(평면 +Z)을 치수 객체로 — 정의점 두 개, 치수선 점에서 offset,
  글자 높이는 치수 블록(*D) 안 글자에서(없으면 DIMTXT × DIMSCALE), 바꾼 글자는 서식 코드를 걷어 그대로(`<>` 유지),
  레이어 이름도. 지금 층(없으면 「1층」)에 넣는다. 각도·반지름·좌표 치수는 지금처럼 *D 블록을 펼친 선으로.
- 그래서 가져온 치수도 고르고·옮기고·글자를 고칠 수 있다. 대신 끝 모양(화살표·사선)과 쉼표 없는 값은 원래대로
  따른다 (§36). 글꼴·소수 자리 같은 나머지 치수 스타일은 아직.
- 내보내기: 회전 치수는 선형 DIMENSION(회전각), 정렬 치수는 정렬 DIMENSION.

## §33 그립 편집·모따기·폴리선 모서리 (2026-11-24)

- 그립: 객체를 고르면 손잡이(파란 네모)가 보이고, 손잡이를 누른 뒤 옮길 곳을 누르면(스냅·직교·`@dx,dy` 입력 됨,
  Esc 취소) 그 점만 고친다 — AutoCAD 처럼 누르고·누르기 (끌기는 상자 고르기와 겹쳐서).
  - 모형 객체(`grip::grips`/`move_grip`): 선 끝·가운데(옮김), 폴리선 꼭짓점, 원 중심·반지름, 호 중심·끝·가운데
    (세 점을 지나는 호로 다시), 타원·문자·블록 참조 기준점.
  - 건축 객체(`archgen::arch_grips`, `ArchReq::Grip`): 벽 끝·가운데, 그리드 끝, 기둥 가운데, 계단 끝, 치수 끝(그 자리
    객체에 다시 묶음)·치수선, 실·대지 꼭짓점, 문·창 가운데(벽을 따라만).
  - 고른 객체 50 개까지만 손잡이를 보인다.
- 모따기(CHA): 두 선을 교점에서 d1·d2 떨어진 곳에서 잘라 선으로 잇는다 (`500` 또는 `500/300`).
- 폴리선 모서리: 모깎기·모따기에서 같은 폴리선의 두 변을 누르면, 그 사이 꼭짓점(앞뒤 변이 직선)을 호(불지)나
  사선으로 바꾼다 (`modify::corner_polyline`). 꺾이는 방향에 따라 불지 부호를 정한다.

## §34 꺾인 계단·도면 목록 시트 (2026-11-25)

- 꺾인(ㄱ자) 계단: 계단에 꺾는 점 `mid`(중심선)를 두면 두 줄기와 참(계단 폭 정사각형)이 된다. 줄기는 참 반 폭만큼
  짧아지고, 단 수는 두 줄기 길이 비례로 나눈다 (`Stair::flights`). 평면은 줄기마다 외곽·디딤판 선, 참 외곽,
  중심선을 따라 꺾인 오름 화살표. 3D 는 단마다 상자, 참은 첫 줄기 끝 높이. 줄기가 폭보다 짧으면 거절.
  계단 도구는 두 점 뒤 Enter 면 곧은 계단, 셋째 점을 누르면 꺾인 계단. 손잡이에 꺾는 점도.
- 도면 목록 시트: 시트 만들기에서 종류 「도면 목록」(또는 SHL). 뷰포트 없이 종이에 모든 시트의 목록 표
  (순번·도면 번호·도면명·축척·층)를 합칠 때마다 새로 그린다 (`Layout::list`, `sheet::list_table`) — 시트를
  더하거나 지우면 목록이 따라 바뀐다. 축척은 첫 뷰포트에서 셈.
- 새 시트의 층은 지금 층이 기본.

## §35 뷰포트 편집·손잡이 끌기 (2026-11-25)

- 시트 탭에서 옆 칸 「뷰포트」: 축척(1:N, 표준 축척 목록), 종이 위 크기·위치, 모형에서 보는 가운데를 바로 고치고,
  「모형에 맞춤」 은 그 층 모형 전체가 들어오는 가장 작은 표준 축척과 가운데로 (`sheet::edit_viewport`, 여유 8 %).
  화면에는 뷰포트 테두리를 파란 점선으로. 첫 뷰포트 축척이 바뀌면 표제란의 「1:N」 글자도 바꾼다.
- 배치 하나 바꾸기는 `Editor::set_layout`(`Op::Layouts`) — 되돌리기 한 단계. 시트에서도 되돌리기·다시 하기가 된다
  (되돌리다 시트가 없어지면 모형으로).
- 손잡이 끌기: 손잡이 위에서 끌기를 시작하면 상자 고르기 대신 손잡이를 옮기고, 놓는 곳에 스냅. 누르고·누르기도 그대로.

## §36 치수 종류·스타일·누적 치수 (2026-11-25)

- 치수 종류 `DimKind`: 선형(정렬·회전), 반지름(R), 지름(Ø), 각도(°). 반지름·지름은 a 중심·b 원 위 점, 각도는
  꼭짓점·두 반직선 위 점·호 반지름(offset). 각도는 두 반직선 사이 작은 쪽 호, 반직선이 호까지 안 닿으면 보조선.
  도구: DRA·DDI(원·호를 누르면 누른 쪽으로), DAN(두 선 → 교점 → 호 자리). 원·선 모양은 `shape_at` 명령으로 읽는다.
- 끝 모양(`arrow` — 사선/화살표)과 쉼표(`plain`)를 치수마다 둔다. 새 치수의 기본은 「치수 스타일」(DST, 설정 파일에 기억),
  고른 치수는 속성 칸에서. 가져온 치수는 원래 끝이 SOLID·해치면 화살표, 값은 쉼표 없이(AutoCAD 기본 단위 형식).
- 누적(기준선) 치수: 치수 하나 뒤 `B` 를 치면 다음 점들을 첫 점에서 재고 치수선을 글자 높이 3 배씩 바깥으로 (`C` 연속으로).
- 반지름·지름·각도 치수 옮기기는 통째로, 손잡이는 두 점(과 꼭짓점). DXF·DWG 로 쓰기는 §43.

## §37 선과 호 모깎기·U자 계단 (2026-11-25)

- 선과 호·원 모깎기: 모깎기 원 중심은 선에서 ±r 떨어진 직선과 원에서 R±r 떨어진 원의 교점 — 후보 중 접점이 누른 두 점에
  가장 가까운 것 (`modify::fillet_line_arc`). 선은 누른 쪽 먼 끝에서 접점까지, 호는 접점에서 나눠 누른 쪽을 남기고
  (접점이 호 밖이면 가까운 끝을 늘림), 원은 그대로 둔다.
- U자 계단: 꺾는 점 뒤로(첫 줄기 쪽) 반 폭 넘게 돌아오고 옆으로 계단 폭 이상 떨어진 끝점이면 U자 (`Stair::u_turn`).
  둘째 줄기는 첫 줄기와 나란히 거꾸로, 참은 두 줄기를 덮는 직사각형. 단 수는 두 줄기 길이 비례.

## §38 단면 자동 (2026-11-25)

`arch::Section`(이름, 자르는 선 a→b, 단면도 자리 at)을 두면 평면에는 자르는 선·보는 쪽 화살표·이름(A, A')을,
모형 공간 at 에는 단면도를 그때그때 만든다 (`section::draw`) — 벽·창·바닥을 고치면 단면도도 바뀐다.
단면도 x 는 자르는 선 a 에서의 거리, y 는 절대 높이. 벽은 자르는 선과 중심선이 만나는 곳에 두께(비스듬하면 두께/|sin|,
너무 비스듬하면 5 배까지)로 칠하고, 그 자리에 문이 있으면 인방 위만, 창이면 창대 아래·인방 위와 유리선. 바닥판은 실 경계와
겹치는 구간에 150, 계단은 줄기가 자르는 선과 나란하고 선이 폭 안을 지나면 계단 모양 선. 층마다 바닥선과
「이름 FL+높이」, 지반선, 제목 「단면 A-A'」. 손잡이: 자르는 선 두 끝·단면도 자리, 옮기기는 단면도 자리.
보이는 선·지붕은 §41. 남은 것: 천장, 보, 단면 해치 종류, 기둥·문짝의 보이는 선.

## §39 IFC 내보내기 (2026-11-25)

`ifc::write` — IFC4 STEP 글. 프로젝트·대지·건물·층(바닥 높이) 아래 벽(두께×길이 직사각형 돌출, 높이), 문·창(벽 두께 상자,
OverallHeight·Width), 실(IfcSpace, 이름·면적 LongName, 층고 돌출), 바닥판(IfcSlab 150), 기둥. 글로벌 ID 는 객체 종류·번호
해시로 늘 같게(다시 내보내도 같은 ID). 한글은 `\X2\…\X0\`. 앱 「내보내기 → IFC」, `dsmith ifc`.
벽 구멍은 §41. 남은 것: 계단, 재료·속성 세트, 가져오기.

## §40 레이어 검사 (2026-11-25)

표 서랍 「레이어 검사」: 레이어 이름이 분야 글자(A·S·M·E·P·C·L·G·F·T·I)-주 그룹(영대문자·숫자 2~6 자)[-부 그룹…] 꼴인지

## §41 IFC 벽 구멍·단면 보이는 선·지붕 (2026-11-25)

- IFC: 문·창마다 벽 두께보다 20 두꺼운 IfcOpeningElement 를 놓고 IfcRelVoidsElement(벽 ← 구멍),

## §42 축척별 표현·여러 뷰포트 (2026-11-25)

  1:200 보다 작은 축척(1:200 이상)이면 문 열림 호·창호 기호·실 면적 글자를 빼 단순하게. 시트는 첫 뷰포트 축척으로

- 시트에 뷰포트 더하기(옆 칸 ＋ — 틀의 1/3 크기, 왼쪽 아래, 첫 뷰포트와 같은 가운데·축척)·지우기. 되돌리기 한 단계.

## §43 호와 호 모깎기·돌음 계단·배열 블록·치수 소수 자리·반지름/각도 DIMENSION (2026-11-25)

- 호·원 둘 사이 모깎기: 모깎기 원 중심은 두 원에서 각각 R±r 떨어진 원들의 교점 중 접점이 누른 점에 가까운 것
  (`modify::fillet_arcs`). 호는 접점에서 나눠 누른 쪽을 남기고, 원은 그대로.
- 돌음(나선) 계단: `Stair::spiral`(회전각) — a 중심, b 는 중심선 위 시작점. 안·바깥 반지름은 중심선 ± 폭/2, 단은 같은 각으로
  나눈 부채꼴. 평면은 안·바깥 호·단마다 반지름 선·중심선 호 화살표·UP, 3D 는 단마다 부채꼴(네 모서리) 상자.
  계단 도구에서 `S` → 중심 → 시작점 → 회전각(도, 음수면 시계).
- 배열 블록(MINSERT): 가져올 때 칸마다 블록 참조 하나씩 (속성값이 보이는 배열은 펼침 — §46).
- 치수 소수 자리(`precision` 0~4): 속성 칸·치수 스타일에서. 소수 끝 0 은 뺀다(AutoCAD DIMZIN 처럼 3000.00 → 3000).
  가져온 치수는 머리글 DIMDEC.
- 반지름·지름·각도 치수도 DXF·DWG 에 DIMENSION(반지름·지름·3 점 각도)과 모양 블록 *D 로 쓴다.

## §44 최초 버전 검증 (2026-11-25)

결과와 다시 하는 법은 `docs/verification.md`. 검증용 예제 건물(`demo::demo_building`, `dsmith demo`)과 `dsmith export

펼침(파일 이름에 층·CLI `--level`), 건축 객체만 있는 도면의 객체 수 표시.

## §45 무늬 해치 객체·모든 층 내보내기·반지름/각도 치수 가져오기·단면 가림 (2026-11-25)

검증(§44)에서 나온 한계를 고쳤다.
- 무늬 해치: `Shape::Hatch`(경계 고리 + 무늬 선 정의 + 이름). 가져온 무늬 HATCH 와 해치 도구(H)가 만든 무늬는 이 객체로
  남고, 화면·PDF·고르기는 보이는 도면 단계(`archgen::with_arch_owned`)에서 무늬 선분으로 바꿔 쓴다(번호는 그대로).
  내보내기는 모형에서 HATCH(무늬 정의째)로 — DWG→DXF→DWG→DXF 를 돌아도 ANSI31 이 HATCH 로 남는다. 옮기기·회전·
  대칭은 경계와 무늬 기준점·방향·간격·대시를 함께 바꾼다.
- 모든 층 내보내기(`export::all_levels_model`): 층마다 건물 폭 + 10 m 씩 오른쪽에 나란히, 층 이름 제목. 그리드는 층마다
  복사(새 번호)하고 그 층 치수가 묶인 그리드를 바꿔 준다. 대지·단면은 한 번. 앱 「내보내기 → DWG (모든 층 나란히)」,
  CLI `--all-levels`.
- 가져오기: 반지름·지름·3 점 각도·2 선 각도 DIMENSION 도 치수 객체로 (2 선 각도는 두 선 교점이 꼭짓점, 각 선에서 먼 끝이
  반직선 위 점, 호 점까지 거리가 호 반지름).
- 단면 가림: 자른 면과 보이는 벽을 「t 구간 × 높이」 가림막으로 모아, 보이는 벽을 가까운 것부터 그리며 높이를 다 덮는
  앞 가림막의 t 구간을 뺀다(위·아래 변은 남은 구간만, 세로 변은 끝이 보일 때만). 창 외곽도 같은 가림막으로 자른다.
  높이를 일부만 덮는 것(문·창 자리)은 가리지 않는다 — 열린 곳 너머가 보인다.

## §46 단면의 기둥·계단 입면, 속성(ATTRIB) 블록 (2026-11-25)

- 단면 기둥: 자르는 선이 기둥을 지나면 자른 면(굵은 선·무늬), 보는 쪽에 있으면 보이는 외곽(층 바닥~층고)을 그리고 그
  뒤를 가린다(§45 가림막에 더함).
- 단면 계단: 자르는 선과 나란한 계단 줄기가 보는 쪽에 있으면 단마다 디딤판·챌판 계단 모양 입면으로. 앞 가림막에 완전히
  가려진 줄기는 그리지 않는다.
- 속성 블록: `Shape::Insert::attrs`(태그 + 글자). 글자는 블록 안 좌표로 두어 참조를 옮기고 돌리고 대칭해도 함께 간다.
  화면·PDF 는 펼칠 때(`block::expand`) 참조의 레이어·색으로 그리고, 펼치기(X)하면 보통 글자가 된다.
  - 가져오기: 보이는 ATTRIB 가 있는 참조도 블록 참조로 살리고 ATTRIB(세계 좌표)을 참조의 역변환(`Affine::inverse`)으로
    블록 안 좌표로 바꾼다. 속성값이 있는 배열 블록(MINSERT)은 속성이 첫 칸에만 붙으므로 펼친다.
  - 내보내기: INSERT 에 ATTRIB(세계 좌표·맞춤) — ezdxf 감사 오류 0.
  - 앱: 블록 참조 하나를 고르면 속성 칸에 「속성 태그」 값 칸(바로 고침)과 「속성 더하기…」(태그·값·글자 높이, 블록 아래로
    줄지어 놓임). 태그는 대문자, 빈칸 없이, 참조 안에서 하나씩.
  - 블록 정의 쪽 ATTDEF(기본값·묻는 말)는 아직 없다 — 참조마다 속성을 붙인다.

## §47 IFC 가져오기 (2026-11-25)

`ifc_read::read` — IFC2x3·IFC4 STEP 파일을 외부 라이브러리 없이 읽어 건축 객체로(`.ifc` 를 열기·끌어 놓기·CLI `info`).
평면 CAD 라서 3D 를 다 풀지 않고, 객체의 놓인 자리(IfcLocalPlacement 사슬, Z 는 위로 봄)와 몸체의 바닥 모양(밀어 올린
단면 — 사각형·다각형·원, 잘라 낸 몸체는 첫 몸체, 대응 항목은 원점까지)만 읽는다.
- 길이 단위: IfcSIUnit 접두어(MILLI·CENTI·없음=m) 또는 FOOT·INCH 를 mm 로.
- 층: IfcBuildingStorey(높이 순), 층고는 다음 층까지(마지막은 앞 층고, 하나면 3000).
- 소속: IfcRelContainedInSpatialStructure·IfcRelAggregates 를 위로 따라가 층을 찾고, 없으면 높이가 가까운 아래층.
- 벽(IfcWall·StandardCase·ElementedCase·CurtainWall): 'Axis' 표현이 있으면 그 두 끝 + 바닥 모양을 축에 수직으로 잰 폭이
  두께, 없으면 바닥 모양을 가장 긴 변에 맞춘 상자의 긴 쪽 중심선·짧은 쪽 두께. 이름에 「내벽」·interior 가 있거나 두께
  150 mm 미만이면 내벽. 한쪽 면 기준으로 그린 벽(IfcOpenShell·Revit 등)은 중심선 끝이 닿지 않으므로, 같은 층 두 벽의
  중심선 교점에서 두 두께 안에 있는 끝을 교점으로 옮긴다(`join_corners`) — 평면 생성이 L·T 맞댐으로 잇는다.
- 문·창: IfcRelFillsElement → 구멍 → IfcRelVoidsElement → 벽. 자기 몸체(없으면 구멍 몸체)를 벽 축에 내린 구간의 가운데가
  위치, OverallWidth·Height(없으면 몸체 크기), 창대는 놓인 높이 − 층 높이. 다른 프로그램마다 문 원점이 가운데·끝으로
  다르므로 원점을 쓰지 않는다.
- 실: 바닥 다각형, 이름은 LongName(없거나 우리가 쓴 「… m2」 면 Name).
- 기둥: 바닥 모양 상자. 원기둥은 지름 정사각 (사각 기둥만 있으므로).
- 그리드: IfcGrid 의 IfcGridAxis 선과 이름.
- 계단·슬래브·지붕은 읽지 않는다(바닥판은 실에서 다시 만든다). B-rep·면 모델만 있는 객체는 건너뛴다.
- 시험: 우리 IFC 왕복(예제 건물 — 벽 끝·두께·문 위치·실 면적·층 소속이 같음), IfcOpenShell API 로 만든 파일
  (`crates/draftsmith-core/testdata/`, 한쪽 면 기준 벽·끝 원점 문·원기둥), 미터 단위 + 축선 없는 벽.

## §48 실 찾기 — 평면 그래프의 면 (2026-11-25)

§19 의 반직선 방식(점에서 720 방향으로 쏴 처음 닿는 벽 면)은 직교 평면만 잘 맞았다. 사선 모서리에는 반직선 오차로 잔
꼭짓점이 생기고, ㄱ자처럼 오목한 실은 점에서 안 보이는 부분을 잘라 먹었다. 이제(`archgen::face_around`):
1. 지금 층 벽의 두 면을 두께만큼 늘린 선분으로 모은다 (모서리에서 서로 만나게).
2. 선분끼리 만나는 곳에서 모두 쪼개 평면 그래프를 만들고(꼭짓점은 0.01 mm 로 묶음), 막다른 가지(늘린 끝·벽 끝)를 걷어 낸다.
3. 점에서 살짝 기운 반직선이 처음 닿는 변을 점이 왼쪽에 오게 잡고, 꼭짓점마다 들어온 변의 시계 방향 바로 다음 변으로
   간다 — 점을 품은 면을 한 바퀴 돈다. 넓이가 양수이고 점을 품어야 실(아니면 열린 곳 → 없음).
4. 일직선 위 꼭짓점을 뺀다. 꼭짓점은 안쪽 면의 정확한 교점이다.
문·창은 벽 면을 끊지 않으므로 실 경계는 개구부를 가로질러 닫힌다(전과 같음). 시험: ㄱ자(꼭짓점 6·넓이 정확), 사선 삼각형,
열린 ㄷ자.

## §49 블록 정의 속성(ATTDEF) (2026-11-25)

`Block::attdefs`(태그·묻는 말·기본값 글자, 블록 안 좌표). §46 은 참조마다 속성을 붙였다면, 이제 블록이 속성 정의를 가진다.
- 넣기: 속성 정의가 있는 블록을 넣으면 참조에 기본값으로 속성이 붙는다 — 값은 속성 칸에서 고친다.
- 만들기: 블록 참조에 속성을 붙이고 「블록 기본 속성으로」(EditReq `define_attrs`) — 그 참조의 속성(태그·위치·값)이 블록의
  속성 정의가 된다. 이미 넣은 참조는 그대로. 되돌리기 가능(`Op::Blocks`).
- 가져오기: 블록 참조로 살리는 블록 안의 보이는(상수 아닌) ATTDEF 를 속성 정의로. 블록 안 ATTDEF 는 그리지 않고(AutoCAD 와
  같음) 「표시하지 않은 객체」 로 세지도 않는다.
- 내보내기: 블록 정의 안에 ATTDEF (레이어 0) — ezdxf 감사 오류 0.

## §50 IFC 계단 (2026-11-25)

- 내보내기: 계단마다 IfcStair(곧은 .STRAIGHT_RUN_STAIR. · 꺾인 .QUARTER_TURN_STAIR. · U자 .HALF_TURN_STAIR.)가
  IfcRelAggregates 로 줄기(IfcStairFlight — 자리는 줄기 아래 끝·오르는 방향·그 줄기 시작 높이, 몸체는 길이×폭을 줄기

## §54 곡선 벽 (2026-11-25)

`Wall::bulge` — 중심선이 a→b 를 잇는 호, 폴리선과 같은 볼록 값 tan(중심각/4) (양수면 반시계, 0 이면 곧은 벽, ±1 이 반원).
`length` 는 호 길이, `point_at`·`param` 은 호 위의 점·위치(문·창 `offset` 도 호 길이), `dir` 은 현 방향.

곧은 벽을 전제한 코드(접합·면선·해치·문·창 기호·3D·단면·IFC·실 찾기·시트 범위)를 고치지 않고, 그리기 직전에
`ArchModel::straightened` 로 곡선 벽을 곧은 조각(중심각 5° 이하)으로 나눈다:
- 문·창 구간은 한 조각(현)으로 떼어 그 위에 둔다 — 문·창은 현을 따라 곧게 놓인다(실제 곡선 벽의 문도 대개 곧다). 조각
  위 폭은 현 길이(창호일람표는 원래 폭).
- 조각끼리는 거의 나란한 L 접합이라 면선이 꺾여 이어지고 마구리가 없다. 곡선 벽 끝은 이웃 곧은 벽과 보통처럼 맞댄다.
- 첫 조각은 원래 벽 번호, 나머지는 새 번호(next_id + 100만부터)이고 평면 생성의 주인은 원래 벽으로 돌려 준다 — 고르기·
  속성·손잡이는 곡선 벽 하나로.
- 실 찾기(§48)도 조각 면으로 — 둥근 실 넓이는 5° 다각형이라 참값보다 0.1 % 안쪽으로 작다.
- IFC 는 조각 벽 여럿으로 쓴다(IfcWall 곡선 몸체는 아직).

편집: 도구 AW(곡선 벽: 시작점·지나는 점·끝점, 두께·종류는 벽 도구와 같음). 손잡이는 a·b·호 가운데(끌면 그 점을 지나게
굽힘)·현 가운데(옮김). 속성 「곡선 높이」(현 가운데에서 호까지, 부호는 굽는 쪽, 반원까지) — 0 이면 곧은 벽, 곧은 벽에
값을 넣으면 굽는다. 「반지름」 은 읽기만. 벽 끝을 옮기거나 굽혀 짧아지면 문·창이 벽 안으로 당겨진다.

도구 막대가 1440 px 창에서 두 줄로 넘어가 버튼 간격·목록 폭을 줄이고 곡선 벽은 막대 대신 AW·⌘K·벽 버튼 설명으로 둔다.

## §59 SHX 글꼴로 그리기 (2026-11-25)

`shx` — AutoCAD SHX 를 외부 라이브러리 없이 읽는다: 모양 글꼴(shapes 1.0·1.1), 큰 글꼴(bigfont 1.0 — 앞 바이트 범위 +
2 바이트 코드), 유니코드 글꼴(unifont 1.0). 모양 명세의 벡터(16 방위)·펜·배율·위치 넣고 꺼내기·부분 모양·(dx,dy)·팔분 호·
분수 호·볼록 호·세로 전용(14 — 건너뜀)을 꺾은선 획으로 푼다.

  폭), 세로는 상자 높이 ÷ 위 높이. 처음에 한 배율로 했더니 言·氵 변이 붙는 한자가 깨졌다.
- 큰 글꼴의 인코딩은 모양 번호로 짐작: 「あ」(82A0)·「ア」(8341) 가 있으면 Shift-JIS, 「가」(B0A1)·「하」(C7CF) 가 있으면
  CP949, 「、」(A4A2) 면 GBK. 도면 코드 페이지가 아니라 글꼴 쪽 인코딩으로 바꾸므로, 한국어 도면이 일본어 큰 글꼴을 가리켜도
  한글이 깨진 모양으로 나오지 않고 내장 글꼴로 나온다(AutoCAD 보다 낫게).
- 그리기: 가져올 때 글자에 스타일 이름(`TextShape::style`)과 스타일별 글꼴(§57)을 남기고, 보이는 도면 단계에서
  (`archgen::with_arch_scaled` → `shx::apply`) 그 스타일의 기본·큰 글꼴이 SHX 폴더에 있으면 글자를 획 선분으로 바꾼다
  (객체 번호 그대로 — 고르기·속성은 글자 객체). 글자 높이 = 글꼴 위 높이, 폭 배율·회전·가로 맞춤·세로 맞춤(바탕선·아래·
  가운데·위)·여러 줄(줄 간격 5/3 h). SHX 에 없는 글자는 그 자리에 내장 글꼴 글자로(폭은 Pretendard 진행 폭) 맨 뒤에 덧붙인다.
  화면·PDF·시트 모두 같은 단계를 쓴다. DWG·DXF 로 내보낼 때는 원래 글자 그대로.
- 앱: 명령 SHX(⌘K 「SHX 글꼴 폴더」) — 폴더를 고르면 설정에 남고(다음 실행에도), 다시 부르면 바꾸기·끄기. 표 「글꼴」 의
  「화면·PDF」 칸이 「SHX 로 그림 (…)」 으로 바뀐다.
- 글꼴 파일은 저장소에 넣지 않는다(저작권). 시험은 시험 안에서 만든 작은 모양·큰 글꼴과, 경로를 주면(`SHX=…`) 실제 글꼴로.
  사용자가 준 extfont2.shx(AUGJP 「標準漢字フォント」, 2004)는 일본어 Shift-JIS 큰 글꼴(8,316 모양)로 한글이 없다 — 일본
  한자·가나는 AutoCAD 와 같은 모양으로 그려짐을 확인했다. 한글 큰 글꼴(whgtxt.shx 등)도 같은 길로 그린다.

- 두 한글 글꼴 모두 KS 2,350 자 밖(「똠」 등)은 없다 → 그 글자만 내장 글꼴. ² 처럼 SHX 에 없는 기호도 내장 글꼴.
- 시험 `real_korean_fonts_if_given`(SHX_DIR 폴더가 있을 때만): 인코딩 짐작, 한글·영문 글자가 획으로 풀리는지, 2,350 자 밖이
  없음. 앱에서 txt+whgtxt, romans+HGTXT 스타일 글자(회전 포함)를 열어 확인.

## §60 실무 도면 검증 — 가리개(WIPEOUT)·글자 스타일 내보내기 (2026-11-25)

사용자가 준 실무 도면(DWG 2013, 모형 공간에 도면 틀 12 장, 객체 2,118 · 치수 496 · 블록 참조 44)으로 확인했다(도면은
저장소에 넣지 않음). 읽기 0.22 초, A1 PDF 1.6 초, DWG 내보내기 0.56 초, 내보낸 DXF 의 ezdxf 감사 오류 0, 다시 읽은 객체 수 같음.
치수 496 개는 모두 치수 객체로, 글자는 트루타입(나눔고딕·나눔스퀘어·HY울릉도L) 스타일 — 화면은 내장 글꼴로 대체.
격자선(CEN, [60,-1,0,-1] × LTSCALE 100)이 거의 실선으로 보이는 것은 원래 그렇다(6 m 대시).

찾아 고친 것:
- **가리개(WIPEOUT)** 32 개를 건너뛰고 있어 욕실 변기·세면대 밑으로 바닥 타일 선이 지나갔다. `Shape::Wipeout{ring}` 으로
  읽고(`world_boundary_vertices` — ezdxf 와 같은 식, 꼭짓점 둘이면 사각형), 보이는 도면 단계(`wipeout::apply`)에서
  **그리기 순서상 앞의** 선·폴리선·원·호·타원·선분 묶음을 고리 밖 부분만 남겨 자른다 — AutoCAD 는 가리개를 바탕색 채움으로
  순서대로 그리지만, 화면은 채움→선을 한꺼번에 그려 순서를 지킬 수 없기 때문. 뒤에 그린 것(기구 자신의 선)은 그대로, 글자·
  채움은 자르지 않는다. 가리개 자신은 빈 선분 묶음으로(번호 유지). 내보낼 때는 다각형 WIPEOUT(`Wipeout::polygonal`, 닫는
  꼭짓점까지) — DXF·DWG 왕복 시험. 자른 선은 선 종류 대시를 잃는다(드묾).

### §60-1 글자 스타일 내보내기

내보낸 도면을 다시 읽으니 모든 글자가 Standard(txt) 였다 — 스타일 표를 쓰지 않고 글자에 스타일 이름도 넣지 않았기
때문. AutoCAD 에서 txt 로 한글을 그리면 깨진다(DraftSmith 가 만든 한글 실 이름·표제란도 마찬가지였다).
- 가져올 때 스타일의 글꼴 파일·트루타입 이름·큰 글꼴을 그대로 남기고(`FontUse::file`·`ttf`), 내보낼 때 같은 스타일 표를
  만들어 TEXT·MTEXT·ATTRIB·ATTDEF 에 원래 스타일 이름을 넣는다. 블록 속성값(ATTRIB)을 글자로 펼칠 때도 스타일을 남긴다.
- DraftSmith 가 만든 글자는 스타일 `DRAFTSMITH`(malgun.ttf · 맑은 고딕) — 윈도우에는 늘 있고, 없으면 AutoCAD 가 대체 글꼴로.
- 실무 도면 왕복 뒤 스타일별 글자 수가 같다(돋움 192 · 울릉도M 330 …, 펼친 블록 안 글자는 정의 하나로 셈). DRAFTSMITH 2 개는
  치수 객체로 살리지 못하고 펼친 치수 글자.
- CLI `info` 에 글자 스타일별 글꼴·큰 글꼴·글자 수.

## §61 치수 스타일 왕복 (2026-11-25)

가져온 도면의 치수가 DraftSmith 기본 모양(글자 높이 비례 사선·화살표)으로 그려지고, 내보내면 스타일이 모두 Standard 였다.
- 가져오기: DIMSTYLE 표의 주요 값(`arch::DimStyle` — 글자 DIMTXT·화살표 DIMASZ·사선 DIMTSZ·보조선 DIMEXO/DIMEXE·글자 간격
  DIMGAP·축척 DIMSCALE·길이 배율 DIMLFAC·소수 DIMDEC·0 지우기·단위·글자 자리 DIMTAD·맞춤·화살표 블록·글자 스타일·접두접미
  DIMPOST·색·치수선 넘김)을 `ArchModel::dim_styles` 에, 치수마다 스타일 이름(`Dim::style`)을. 소수 자리는 스타일 DIMDEC(없으면
  머리글).
- 화살표: 스타일 표의 화살표 블록 이름은 acadrust 가 풀지 못해(핸들만) 비어 오므로, 치수 모양 블록(*D) 안에 실제로 넣은
  블록을 그 치수의 화살표(`Dim::arrow_block`)로 삼고 정의를 들여온다. 이때 폭 있는 폴리선은 채움으로(`wide_fills` — 곧은 변은
  사각, 호 변은 고리 조각) — 국내 도면에 흔한 점(·) 화살표가 채운 점으로 나온다.
- 그리기: 스타일이 있으면 화살표 블록을 화살표 크기 배율로 치수선 끝에 바깥(+x)을 향해, 없으면 사선(DIMTSZ>0) 또는 채운 화살표
  (길이 DIMASZ, 폭 1/3), 보조선은 DIMEXO 띄우고 DIMEXE 넘김, 글자는 DIMTAD=0 이면 치수선 가운데·아니면 DIMGAP 위, 값에 DIMLFAC
  배율·DIMPOST 접두접미. 모든 길이 × DIMSCALE. 스타일 없는 치수(DraftSmith 가 만든 것)는 전과 같다.
- 확인: 실무 도면의 치수 496 개(스타일 SDIM-100: 글자 2·화살표 0.8·보조선 1/1 × 100, 화살표 블록 _CIDOT = 폭 0.5 원 폴리선)를
  AutoCAD 가 저장한 모양 블록(*D)과 겹쳐 보았다 — 보조선 띄움·넘김 100, 화살표 배율 80 이 같다.
- 내보내기: DIMSTYLE 표에 가져온 스타일 값을 되쓰고, DraftSmith 치수용 `DRAFTSMITH`(글자 2.5 · 사선 1.25 · 축척 100 · 글자
  스타일 DRAFTSMITH). DIMENSION 에 스타일 이름. 왕복 시험(DXF·DWG): 스타일 이름·값·소수 자리.
- 속성 칸에 「치수 스타일」·「화살표」.
- 남은 것: 일반 객체의 폭 있는 폴리선(이 도면 130 개 — 굵은 틀·단면 표시)은 아직 가는 선으로 그린다. 별도 모양으로 다룰 일.

## §62 글자 고치기·찾아 바꾸기 (2026-11-25)

- 두 번 누르기: 도구가 없을 때 글자를 두 번 누르면 「글자 고치기」(여러 줄이면 여러 줄 칸), 실을 두 번 누르면 실 이름. 그 밖은
  전처럼 화면 맞춤. `Editor::set_text`(빈 글자는 거부 — 지우기는 Delete).
- 찾아 바꾸기(FIND, ⌘K 「찾아 바꾸기」): 모형 글자·블록 속성값·실 이름·치수 덮어쓴 글자에서 찾을 글자를 모두 바꾸고 바꾼 곳
  수를 알린다. 한 작업(`Op::Batch` = 글자 바꾸기 + 건축 모델)이라 ⌘Z 한 번에 되돌린다. 먼저 `count_text` 로 세어 없으면 그대로.
- 고친 결함: 고른 객체의 속성 칸을 보이는 도면에서 읽어, SHX 로 그린 글자·가리개에 잘린 선이 「해치 무늬」 로 보였다 —
  모형 객체는 원래 모양에서 읽는다(`pick_at`·`selection_info`).

## §63 모형 공간 도면 틀마다 PDF (2026-11-25)

국내 실무 도면은 배치 대신 모형 공간에 도면 틀 블록을 여러 장 나란히 두는 일이 흔하다(받은 실무 도면: 틀 블록
`Ha1h_sheet` × 12, 42,000 × 29,700 = A3 1:100). `frames::find`:
- 틀: 두 번 이상 넣은 블록 중 범위가 종이 비율(√2 ± 3 %)인 것, 여럿이면 가장 큰 것. 없으면 같은 크기로 두 번 이상 나온 종이
  비율 닫힌 사각형(4 점 폴리선). 같은 자리 겹침은 하나로. 위 줄부터(틀 높이 반 단위로 줄을 나눔)·왼쪽부터.
- 용지·축척: 틀 크기를 A4~A0(가로·세로) × 표준 축척(1~3000, 28 개) 중 가로·세로 오차가 가장 작은 조합(2 % 안). 못 맞추면 그
  틀은 뺀다.
- PDF(`pdf::export_frames`): 틀마다 한 쪽, 그 용지·축척·여백 0 — 틀이 용지 끝에 맞는다. 쪽마다 그 틀에 걸치는 객체만 넘겨
  (도면 전체를 쪽마다 다시 펼치면 12 쪽에 19 초 → 2.1 초).
- CLI `dsmith pdf --frames 도면.dwg 출력.pdf` (틀 목록 출력), 앱 PDF 「대상 → 모형의 도면 틀마다」.

## §64 편집마다 다시 만드는 비용 측정·원호 조각 수 (2026-11-25)

`dsmith bench` 에 「보이는 도면」(편집마다 앱이 다시 만드는 단계) 시간을 더했다(SHX 폴더는 환경 변수 DSMITH_SHX).
실무 도면(모형 객체 2,118 → 블록을 펼쳐 56,115): 읽기 0.22 초 · 보이는 도면 44 ms · 선분 펼치기 ~200 ms · 바이너리 17 ms.
선분이 123 만 개였는데, 점선 때문이 아니라(점선을 꺼도 122 만) 단열재 표시(INS) 폴리선 — 꼭짓점 ~1,000 · 볼록 호 ~680 개짜리
수백 개 — 의 작은 호가 늘 최소 8 조각으로 펼쳐졌기 때문이었다.
- 원호 조각 수의 최소를 「45° 마다 한 조각」(온 원 8 · 반원 4 · 사분원 2)으로: 실무 도면 123 만 → 100 만 선분(27.6 → 22.8 MB),
  15 만 객체 표본 102 만 → 58 만. 반지름 50 mm 반원이 4 조각이면 1:100 출력에서 0.5 mm 크기라 보이지 않고, 화면을 아주 크게
  키우면 각이 조금 보인다.
- 남은 큰 몫(선분 펼치기 ~200 ms + 20 MB 남짓을 화면으로 보내기)은 편집마다 도면 전체를 다시 만드는 구조 탓이다. 다음 단계:
  바뀐 객체만 다시 펼쳐 보내는 증분 표시(객체별 표시 데이터 캐시 + 화면의 부분 갱신), 점선 무늬를 셰이더에서 그리기.

## §65 폭 있는 폴리선 (2026-11-25)

실무 도면에서 폭 있는 폴리선 130 개(표제란 굵은 테두리 20·85, 도면 제목 막대 180·378, 끝이 뾰족한 지시선 화살표 0→폭)를
가는 선으로 그리고 있었다. `Shape::Wide { points, closed, widths }` — 꼭짓점·볼록 값은 폴리선과 같고 꼭짓점마다 그 변의
(시작 폭, 끝 폭).
- 가져오기: LWPOLYLINE 고정 폭(있으면 모든 변) 또는 꼭짓점 폭, 옛 POLYLINE 은 꼭짓점 폭이 0 이면 기본 폭. 폭이 하나라도 있으면
  Wide, 아니면 전처럼 Polyline. (치수 화살표 블록 안에서는 §61 의 채움 그대로.)
- 그리기(`drawing::wide_quads`): 호는 꼭짓점으로 펼쳐 폭을 길이 비례로 잇고, 변마다 사각형, 꺾인 곳은 바깥 면을 맞대는
  마이터(반각 cos < 0.25 면 빗면)로 메운다. 화면·PDF 는 삼각형 채움 — 선 굵기와 관계없이 도면 단위 폭.
- 옮기기·돌리기·대칭·크기: 폴리선처럼 옮기고 폭은 평균 배율(√|det|)로.
- 내보내기: LWPOLYLINE 꼭짓점 폭, 모두 같으면 고정 폭 — DXF·DWG 왕복 시험.
- 고르기(띠 바깥에서 거리)·속성(꼭짓점·닫힘·폭)·스냅(꼭짓점)·손잡이(꼭짓점마다, §67). 편집은 §67.

## §66 객체별 표시 데이터 캐시 (2026-11-25)

§64 에서 편집마다 도면 전체를 선분으로 다시 펼치는 데 ~200 ms 가 들었다. `display::segments` 의 객체 하나 펼치기를 `emit` 으로
떼고, `SegCache` 가 객체 번호마다 (그때의 객체, 펼친 선분·삼각형)을 들고 있다가 `segments_cached` 에서 **같은 객체면 붙이기만**
한다(객체 비교는 `PartialEq`). 원점·원호 허용 오차가 도면 범위에서 나오므로 범위가 바뀌거나 레이어(켜기·색)·선 종류가 바뀌면 모두
다시. 결과는 늘 `segments` 와 같다(시험).
- 앱: 열린 도면마다 캐시(`Open::seg_cache`), `display_data` 가 쓴다. 새로 열면 비워진다.
- 측정(`dsmith bench`, 한 객체를 바꾼 뒤): 실무 도면 201 → 41 ms, 15 만 객체 표본 202 → 29 ms (남은 몫은 붙이기와 객체 비교).
- 남은 것: 보이는 도면 다시 만들기(~44 ms), 20 MB 남짓 표시 데이터를 화면으로 다시 보내기 — 바뀐 부분만 보내려면 화면(WebGL
  버퍼)의 부분 갱신이 필요하다.

## §67 폭 있는 폴리선 편집 (2026-11-25)

자르기·연장·간격 띄우기·폴리선 모서리(모깎기·모따기)를 폭 있는 폴리선에도: `Shape::thin` 으로 가운데 폴리선과 대표 폭(첫 변의
시작 폭)을 꺼내 기존 폴리선 편집을 그대로 하고 `Shape::widen` 으로 고정 폭을 되붙인다(`modify::pieces`·`rebuild`·
`corner_polyline`·`edit::offset_shape`). 꼭짓점마다 폭이 다르던 것(끝이 뾰족한 화살표 등)은 편집하면 고정 폭이 된다 — 그런
객체는 보통 자르지 않는다. 손잡이는 꼭짓점마다(폭 그대로). 다른 객체의 자르기·연장 경계로도 쓰인다(가운데 선).

## §68 화면 부분 갱신·글자 스타일 유지 결함 (2026-11-25)

- 부분 갱신: `SegCache` 가 객체마다 마지막 결과 속 자리(선분 시작·수, 삼각형 시작·수)를 기억한다. 다음 결과에서 범위·레이어·선
  종류·객체 수가 같고 **다시 펼친 객체의 선분·삼각형 수가 그대로**면, 그 객체들의 자리만 담은 `DSP1` 묶음을 만든다
  (`patch_bytes`). 앱 `display_update`(편집 뒤 「보던 자리 그대로」 다시 그릴 때만)가 이것 또는 전체(`DSD3`)를 보내고, 화면은
  `DSP1` 이면 선·굵은 선·삼각형 버퍼의 그 자리만 `bufferSubData` 로 덮어쓴다. 처음 열 때·범위가 바뀔 때·객체가 늘거나 줄 때는
  전처럼 전체. 옮기기·색 바꾸기처럼 흔한 편집은 바뀐 객체 몇 개만 보낸다(실무 도면에서 전체 20 MB 남짓 → 수 KB).
- 결함: 글자를 옮기거나 돌리면(`Shape::transformed`) 스타일 이름이 빈칸이 되어, SHX 큰 글꼴로 그리던 한글이 내장 글꼴로
  바뀌었다(§59 때 넣은 빈 스타일). 스타일을 그대로 둔다 — 앱에서 SHX 글자를 옮겨 보다가 찾았다. 시험 추가.

## §69 스냅 색인 캐시 — 편집 한 번의 비용 1.1 초 → 0.13 초 (2026-11-25)

「보이는 도면」 단계(44 ms)를 나눠 재다가(복제 7 · 블록 펼치기 11 — 49,045 객체 · 생성 7 · 가리개 11 ms) 편집마다 다시 만드는
색인도 쟀더니 **스냅 색인이 690~780 ms** 로 가장 컸다(실무 도면 스냅 점 190 만 — 단열재 폴리선의 꼭짓점·중간점·호 중심).
고르기 색인 24 ms, 문자 데이터 11 ms.
- `SnapCache`: 객체마다 넣은 스냅 점을 기억하고, `drawing::align` 으로 이전·지금 객체 목록의 같은 앞부분·뒷부분을 맞춰 바뀐
  가운데의 점만 R*-tree 에서 빼고(`remove`) 넣는다(`insert`) — 끝에 더하기·가운데 지우기·제자리 고치기 모두 가운데만. 레이어가
  바뀌었거나 바뀐 점이 전체의 1/3 을 넘으면 새로 쌓는다(`bulk_load`). 객체 목록도 가운데만 갈아 끼운다(전체 복사가 큰 도면에서
  수십 ms). 결과는 늘 새로 만든 색인과 같다(시험: 고치기·지우기·더하기).
- 측정(`dsmith bench`, 한 객체를 바꾼 뒤): 실무 도면 781 → 9 ms, 15 만 객체 표본 308 → 9 ms. 처음 열 때는 전처럼 새로 쌓는다
  (실무 도면 0.8 초).
- 편집 한 번에 앱이 하는 일(실무 도면): 보이는 도면 44 + 표시 데이터 41 + 스냅 9 + 고르기 24 + 문자 11 ≈ 130 ms(전에는
  스냅만 700 ms 남짓). 남은 몫을 줄이려면 블록 펼치기·가리개 자르기·고르기 색인도 같은 방식으로.

## §70 바이너리 응답이 숫자 배열로 오는 환경 — base64 로 (2026-11-26)

시험 환경(Linux WebKitGTK)에서 표시 데이터(`tauri::ipc::Response`)가 ArrayBuffer 가 아니라 JSON 숫자 배열로 와서, 실무 도면을
처음 열 때 22.8 MB 전달에 9.9 초가 걸렸다(§6 의 「느린 경로」). macOS·Windows 에서 어떻게 올지는 실측 전이라 모른다 — 어느
쪽이든 버티게:
- 앱을 띄운 뒤 한 번 `probe_binary`(4 바이트)를 불러 ArrayBuffer 로 오는지 본다.
- 오면 전처럼 `display_data`·`display_update`·`text_data`(바이너리). 안 오면 `display_b64`(선·삼각형 또는 부분 갱신 묶음과
  문자 데이터를 base64 글 두 개로)를 받아 `atob` 로 푼다. 같은 실무 도면에서 9.9 초 → 0.74 초(release 앱, 읽기 0.44 초·
  올리기 0.07 초). 상태 막대에 「base64」 로 표시.
- 3D 보기 데이터는 건축 객체로 만든 작은 것이라 그대로.

## §71 고르기 색인도 바뀐 객체만 (2026-11-26)

§69 다음으로 남은 몫 중 고르기 색인(편집마다 새로 쌓기, 실무 도면 23 ms)을 스냅 캐시와 같은 방식으로 바꿨다.
- 스냅 색인과 달리 고르기 색인은 객체 **번호**를 나무에 담아서, 가운데 객체를 지우거나 넣으면 뒤 객체 번호가 모두 밀린다.
  그래서 나무에는 객체마다 붙인 고정 id 를 넣고, `pos`(id → 객체 번호) 표로 바꿔 읽는다. 번호가 밀리면 나무는 그대로 두고
  뒤쪽 표만 고친다(15 만 객체도 u32 쓰기라 1 ms 안).
- 바뀐 범위는 스냅 캐시가 `drawing::align` 으로 이미 맞춘 것(`SnapCache.diff`)을 같이 쓴다 — 객체 목록을 두 번 비교하지 않으려고.
  스냅 캐시가 새로 쌓았으면(처음·레이어 바뀜·시트 바꿈) 고르기 색인도 새로. 바뀐 것이 1/3 을 넘거나, 지운 id 가 쌓여 표가
  객체 수의 두 배를 넘어도 새로.
- 결과는 늘 새로 만든 색인과 같다(시험: 고치기·가운데 지우기·가운데 넣기·끝에 더하기 뒤 상자 고르기·점 고르기 비교).
- 측정(`dsmith bench`, 한 객체를 바꾼 뒤): 실무 도면 22.7 → 0.1 ms, 15 만 객체 표본 79 → 0.1 ms.
- 편집 한 번에 앱이 하는 일(실무 도면): 보이는 도면 41 + 표시 데이터 37 + 스냅 8 + 고르기 0.1 + 문자 11 ≈ 100 ms.

## §72 보이는 도면 캐시 — 편집 뒤 바뀐 모형 객체 몫만 (2026-11-26)

§71 뒤 편집 한 번에 가장 큰 몫은 「보이는 도면」(`archgen::with_arch_scaled`, 실무 도면 약 40 ms)이었다. 쪼개 재 보니
복제 6 · 블록 펼치기 12 · 해치 선분 4 · 가리개 7 ms 와 건축 객체 선이었다(가져온 치수는 건축 객체 `arch.dims` 라 치수가 많은
도면에서는 이 몫도 크다 — 15 만 객체 표본 21 ms).
- `shown::ShownCache`: 모형 객체마다 남긴 것(처리한 자기 자신, 펼친 블록 객체 수, SHX 에 없어 맨 뒤에 붙는 글자, 가리개가
  있는지)을 기억한다. 앱은 지난 결과 도면을 캐시에 돌려주고, 캐시는 `drawing::align` 으로 바뀐 모형 객체 범위를 찾아 그 몫만
  다시 처리해 모형 부분·펼친 부분에 갈아 끼운다. 뒤 번호가 밀리면 펼친 객체의 주인 번호와 가리개 자리만 고친다.
- 가리개는 자기보다 **뒤의** 객체를 못 가리므로, 바뀐 객체(옛것·새것)에 가리개가 없으면 나머지 객체의 잘린 모양은 그대로다.
  바뀐 객체만 뒤 가리개들로 자른다(`wipeout::clip`). 바뀐 객체에 가리개가 있거나 블록 정의·레이어 「0」 자리·글자 스타일·
  SHX 폴더가 바뀌면 새로 만든다.
- 건축 객체 선(꼬리)은 건축 모델·축척·레이어·선 종류가 같으면 그대로 두고, 다르면 꼬리만 새로 만든다. 블록 정의·배치·
  건축 모델 같은 큰 필드도 같으면 넘겨받은 것을 그대로 쓴다.
- 이를 위해 `shx::Styles`(글자 하나를 획으로)·`wipeout::{wipe_of, clip, hide}`(객체 하나를 자르기)·
  `archgen::{needs_shown, generate_arch}` 로 나눴다. 기존 `apply`·`with_arch_scaled` 는 이것들을 써서 그대로 동작한다.
- 결과는 늘 `with_arch_scaled` 와 같다(시험: 가리개 앞 선 고치기·가운데 지우기·넣기·가리개 품은 블록 넣기·건축 객체만 바꾸기·
  결과를 안 돌려줄 때 — 객체·주인·레이어·선 종류 비교).
- 앱: 지난 `view` 가 캐시가 만든 것일 때만 돌려준다(배치를 합친 종이 도면이면 새로).
- 측정(`dsmith bench`, 한 객체를 바꾼 뒤): 실무 도면 38 → 6.8 ms, 15 만 객체 표본 53 → 12 ms. 남은 몫은 객체 목록 맞추기
  (`align`, 15 만 표본 7.5 ms — 스냅 캐시도 같은 일을 한 번 더 한다)와 건축 모델 비교(3 ms).
- 편집 한 번에 앱이 하는 일(실무 도면): 보이는 도면 7 + 표시 데이터 37 + 스냅 8 + 고르기 0.1 + 문자 11 ≈ 65 ms.

## §73 표시 데이터 캐시 — 지우기·넣기에도 뒤 객체는 그대로, 부분 갱신은 이어 붙이지 않고 (2026-11-26)

§72 뒤 편집 한 번의 가장 큰 몫은 표시 데이터(§66 `segments_cached`, 실무 도면 37 ms)였다. 재 보니:
- §66 캐시는 객체를 **같은 번호끼리** 비교해서, 가운데 객체 하나를 지우면 뒤 객체가 모두 바뀐 것으로 잡혀 다시 펼쳤다
  (실무 도면 28,050 객체 · 91 ms). → `drawing::align` 으로 앞뒤 같은 객체를 맞추고, 가운데만 같은 번호끼리 비교한다.
  목록을 통째로 빼고 넣으면 항목 옮기기만 수십 ms 라, 같은 자리는 제자리에서 고치고 객체 수가 달라진 만큼만 넣고 뺀다.
- 도면 범위(원점·허용 오차의 기준)를 편집마다 모든 객체에서 다시 쟀다(8 ms). → 객체마다 범위를 기억하고 바뀐 객체만 잰다.
  캐시 항목을 객체·펼친 것·범위 세 목록으로 나눠, 범위만 훑을 때 큰 항목을 읽지 않게 했다(15 만 표본 10 → 1 ms 남짓).
- 부분 갱신(§68)으로 보낼 때도 전체 선분(100 만 개, 22.8 MB)을 이어 붙인 뒤 바뀐 자리만 잘라 썼다(약 20 ms).
  → `display::update_bytes`: 부분 갱신이 되면 캐시의 객체별 결과로 바로 묶음을 만들고, 안 될 때만 이어 붙인다. 앱의
  `display_update`·`display_b64(update)` 가 이것을 쓴다. 부분 갱신 여부는 다시 펼친 객체의 선분·삼각형 수가 그대로인지로
  (그러면 모든 객체 자리가 그대로다).
- 결과는 늘 새로 만든 것과 같다(시험: 색 바꾸기·레이어 끄기·더하기·가운데 지우기·넣기·범위가 넓어지는 객체, 부분 갱신
  묶음의 선분·색이 새로 만든 전체의 그 자리와 같은지).
- 측정(`dsmith bench`): 실무 도면 — 제자리 고치기 뒤 보낼 데이터 37 → 8 ms(부분 갱신 969 바이트), 가운데 지우기 뒤 91 → 29 ms
  (객체 수가 바뀌어 전체를 보낸다). 15 만 객체 표본 — 보낼 데이터 18 ms. 남은 몫은 객체 목록 맞추기(`align`)다.
- 편집 한 번에 앱이 하는 일(실무 도면, 제자리 고치기): 보이는 도면 7 + 표시 데이터 8 + 스냅 8 + 고르기 0.1 + 문자 11 ≈ 35 ms.

## §74 문자 데이터는 표시 데이터 캐시의 원점으로 (2026-11-26)

§73 뒤 편집 한 번의 가장 큰 몫은 문자 데이터(`display::texts`, 실무 도면 7.5 ms)였고, 그중 6.5 ms 가 원점(도면 범위 가운데)을
구하려고 모든 객체의 범위를 다시 재는 데 들었다. 표시 데이터 캐시(§73)가 객체별 범위로 이미 같은 범위를 안다.
- `display::texts_at(d, 원점)`, `SegCache::origin()`. 앱은 보이는 도면을 다시 만들 때마다 세대 번호(`era`)를 올리고, 표시
  데이터를 만들 때 그 세대를 적어 둔다(`seg_era`). 문자 데이터는 세대가 같을 때만 캐시 원점을 쓰고, 아니면 전처럼 잰다.
- 그래서 화면(`redraw`)은 표시 데이터와 문자 데이터를 동시에(`Promise.all`) 부르던 것을 **차례로** 부른다 — 문자 쪽이 먼저
  돌면 지난 원점을 쓸 수 있어서. base64 경로(`display_b64`)는 한 번에 둘 다 만드니 그대로.
- 결과는 같다(시험: 캐시 원점으로 만든 문자 데이터 = `texts`). 측정: 실무 도면 7.5 → 0.3 ms, 15 만 객체 표본 11.5 → 1.9 ms.
- 편집 한 번에 앱이 하는 일(실무 도면, 제자리 고치기): 보이는 도면 7 + 표시 데이터 8 + 스냅 8 + 고르기 0.1 + 문자 0.3 ≈ 24 ms.

앱 확인(release, Linux 가상 화면, 실무 도면 — §72·§73·§74 함께): 글자 지우기·평면 블록 참조 지우기·글자 손잡이로 옮기기 뒤
화면이 바뀌고, 되돌리면 도면 영역이 처음 화면과 픽셀까지 같다(다른 픽셀 0).

## §75 가리개에 잘린 점선은 무늬를 지킨다 (2026-11-26)

§60 의 가리개 자르기는 잘린 객체를 선분 묶음(`Shape::Segments`)으로 바꾼다. 화면은 선분 묶음을 언제나 실선으로 그리므로
(SHX 글자 획·해치 무늬도 선분 묶음이라 선 종류를 입히면 안 된다) 잘린 점선·중심선이 실선이 됐다.
- 자르기 **전에** 화면과 같은 규칙으로 무늬를 끊어 두고, 끊은 대시들을 자른다. 그러면 가리개 밖 대시는 잘리지 않은 선을
  그렸을 때와 같은 자리에 남는다(무늬 위상 그대로). 잘리지 않은 객체는 전처럼 화면이 무늬를 입힌다.
- 규칙을 한 곳에 두려고 화면 쪽을 `display::line_chains`(모양 → 꺾은선, 점선 폴리선은 꼭짓점마다 무늬를 새로)·
  `display::dash_lines`(꺾은선 → 대시, 너무 잘거나 반복이 너무 많으면 실선)로 나눠 가리개 자르기도 쓴다. 닫힌 폴리선의
  닫는 변도 화면과 같이 자른다.
- `wipeout::clip` 이 도면의 선 종류 무늬를 받는다. 보이는 도면 캐시(§72)는 선 종류 무늬가 바뀌면 새로 만든다.
- 시험: 대시 [1, −1] 선이 x 5.5~8.5 가리개를 지나면 대시 [6,7] 은 지워지고 [8,9] 는 [8.5,9] 로, 나머지는 원래 자리.
  실무 도면은 가리개 밑을 지나는 점선이 없어 PDF 12 쪽이 바꾸기 전과 픽셀까지 같다.

## §76 폭이 변하는 폴리선을 고쳐도 폭이 변한 채로 (2026-11-26)

§67 은 폭 있는 폴리선을 폴리선으로 고친 뒤 **첫 폭 하나**를 모든 꼭짓점에 되붙여, 가늘어지는 폴리선(화살표 등)이 고른
폭이 됐다.
- `drawing::rewiden(원래, 고친 것)`: 고친 폴리선의 변마다 그 변 가운데가 가장 가까운 원래 변을 찾고, 변 양 끝을 그 원래 변에
  비춰 그 자리 폭(시작 폭 → 끝 폭, 길이 비례)을 준다. 자르면 잘린 자리 폭, 연장하면 끝 폭, 모깎기·모따기로 생긴 변은 앞뒤
  변의 폭을 잇는다. 폭이 모두 같으면 전처럼 고정 폭.
- `drawing::rewiden_parallel`: 간격 띄우기는 꼭짓점이 1 대 1 이라 꼭짓점마다 폭을 그대로 옮긴다(비춰 보면 안쪽 모서리가
  어긋난다). 꼭짓점 수가 다르면 `rewiden`.
- 자르기·연장(`modify::rebuild`)·모깎기·모따기(`corner_polyline`)·간격 띄우기(`offset_shape`)가 쓴다.
- 시험: ㄱ자 (1→3, 3→5) 를 둘째 변 가운데에서 자르면 (3→4), 선 하나로 줄면 (1→2), 모깎기 뒤 앞뒤 변 (1→2.6)·(3.4→5),
  간격 띄우기는 그대로, 가늘어지는 선(0→100) 을 가운데에서 자르면 (0→50).

## §77 곡선 벽을 IFC 에 곡선 몸체로 (2026-11-26)

§54 는 IFC 를 곧은 조각 벽(5° 마다 `IfcWall` 하나)으로 냈다. 다른 프로그램에서 벽 하나가 여러 개로 보이고 면이 각졌다.
- 곡선 벽 하나 = `IfcWall` 하나. 자리는 호 중심, 몸체는 바깥 호·안쪽 호(반지름 ± 두께/2)와 양 끝 직선으로 된 띠를
  IFC4 `IfcIndexedPolyCurve`(`IfcArcIndex`·`IfcLineIndex`, 호를 근사 없이 그대로)로 그려 높이만큼 돌출한다. 중심선도
  `Axis` 표현에 세 점 호로 함께 쓴다 — 다시 읽을 때 곡선 벽으로 되살리려고.
- 문·창: 호 위 그 자리(`Wall::point_at`)에 접선 방향으로 둔다. 구멍은 호가 처진 만큼(폭²/8r) 양쪽으로 더 두껍게.
- 읽기(`ifc_read`): 중심선이 세 점 호 하나면 `Wall::bulge_through` 로 곡선 벽, 두께는 몸체 점들이 호 중심에서 떨어진
  거리의 폭. 문·창 가운데는 몸체 가운데를 중심선 호에 내린 호 길이.
- 시험: 반지름 5 m 반원 벽 + 문을 쓰고 다시 읽으면 끝점·볼록 값·두께·문 위치·폭이 같다. ifcopenshell 로 읽으면 벽이 반원
  띠(꼭짓점 457 — 진짜 호), 부피 9.045 m³ (계산 π·5·0.2·3 − 문 구멍 0.9·0.2·2.1 = 9.047).
- 3D 보기·단면·평면은 여전히 곧은 조각 모델(`straightened`)로 그린다.

치수 글꼴(로드맵 M2 「남은 것」)은 따로 할 일이 없었다: 치수 문자는 치수 스타일의 글자 스타일(DIMTXSTY)을 달고 만들어지고
(§61), 글자 스타일 표는 모두 글꼴 목록에 들어가므로(§59) 그 스타일이 SHX 면 치수 글자도 SHX 획으로 그린다. 실무 도면의
치수 496 개는 스타일 `H1`(트루타입 나눔고딕)이라 내장 글꼴로 그린다.

## §78 IFC 돌음 계단 왕복·가로로 밀어 낸 보 가져오기 (2026-11-26)

- 돌음 계단 내보내기: 전에는 바깥 원(24 각형) 몸체 하나라 안쪽 반지름·회전각·단 수를 잃었다. 이제 `IfcStair`(.SPIRAL_STAIR.)
  아래 줄기 `IfcStairFlight`(.SPIRAL.) 하나 — 몸체는 안·바깥 호 띠(§77 과 같은 `IfcIndexedPolyCurve`, 반 바퀴를 넘어도 되게
  한 쪽에 호 둘), 중심선(`Axis`)도 호 둘, 단 수는 `NumberOfRisers`. 한 바퀴를 넘는 계단은 평면 띠가 겹치므로 몸체만 한 바퀴
  조금 못 미치게 그리고 중심선은 그대로.
- 돌음 계단 가져오기(전에는 건너뜀): 계단 자신과 줄기에서 중심선·몸체·단 수를 찾는다. 중심선이 같은 호 여러 개면 첫 호로
  중심·회전 방향을 구해 호 수만큼 곱한다. 중심선이 없으면(다른 프로그램) 몸체 점들로 — 중심은 둘레 상자 가운데, 회전은
  각도 사이 가장 큰 틈을 뺀 나머지(반시계), 시작은 틈 다음, 반지름은 점까지 거리의 가운데. 폭은 몸체 점까지 거리의 폭.
- 가로로 밀어 낸 보(Revit 등 — 돌출 자리 축이 수평이고 단면이 보 단면): 전에는 건너뛰었다. 돌출 몸체를 3D 로 풀어
  (`solid3`: 자리 축 z·x 를 3D 로, 단면 꼭짓점과 돌출 벡터) 돌출이 거의 수평이면 단면 가운데에서 돌출 벡터만큼이 보 중심선,
  단면의 수평 폭이 폭, 높이 폭이 춤. 세로로 밀어 올린 보(우리 내보내기)는 전처럼 바닥 모양으로.
- 계단·보만 있는 IFC 도 읽는다(전에는 벽·실·기둥이 없으면 오류).
- 시험: 270° 돌음 계단(반지름 1.2 m·폭 1 m·15 단)·시계 방향 135° 왕복이 같다. 몸체만 있는 270° 띠에서 회전각·시작 방향을
  짐작. Revit 식 보(자리 축 z = 세계 x, 단면 600×300, 5 m) 가 (1000,2000)→(6000,2000), 폭 300·춤 600. ifcopenshell 로 읽은
  돌음 계단 줄기 부피 16.960 m³ (계산 16.965).
- 슬래브는 모델에 바닥판 객체가 없어(내보낼 때 실에서 만든다) 가져오지 않는다.

## §79 3D 보기에서 곡선 벽·돌음 계단을 매끈하게 (2026-11-26)

3D 보기는 곡선 벽을 5° 곧은 조각으로 세우고(§54) 삼각형마다 법선 하나로 그늘을 넣어(§24 `DSM3`) 조각마다 세로 줄이 보였다.
조각이 휜 차이 자체는 반지름 5 m 에서 5 mm 정도라, 줄은 모양이 아니라 그늘·틈 때문이었다.
- 형식 `DSM4`: 삼각형마다 꼭짓점 법선 셋 (76 바이트). 화면(`view3d.js`)도 꼭짓점 법선을 그대로 쓴다.
- 꼭짓점 법선(`Mesh::vertex_normals`): 같은 자리(1 mm 격자)에서 만나는 면 중 방향이 30° 안쪽인 면들의 법선을 넓이로
  평균 — 꺾인 곳(벽 모서리 90° 등)은 그대로 날카롭다.
- 곡선에서 나온 삼각형 범위와 호 중심을 기록(`Mesh::radial` — 곡선 벽 조각은 `straightened` 의 조각 → 원래 벽으로, 돌음
  계단은 중심)하고, 그 범위의 옆면(수평 법선이 반지름 방향과 거의 같은 면)은 꼭짓점마다 그 자리의 반지름 방향을 법선으로.
- 곡선 벽 조각은 모서리를 조각 방향의 수직이 아니라 호 중심에서 뻗는 방향으로 두께/2 만큼 놓는다. 전에는 이웃 조각 모서리가
  9 mm 쯤 벌어져 바깥 면에 틈(조각 끝면)이 보였다.
- 시험: 반원 벽 옆면 꼭짓점 법선이 모두 반지름 방향, 곧은 벽 상자는 모든 꼭짓점 법선이 제 면 법선 그대로.
  앱(Linux 가상 화면)에서 곡선 벽·돌음 계단이 이어진 곡면으로 보이는 것을 확인.

## §82 객체 고유 번호 (2026-11-26)

공동작업(Loro, §80)·선택 유지·변경 비교의 전제. 지금까지 객체는 목록 번호로만 가리켰다(지우거나 넣으면 밀린다).
- `Entity.id: u64` (0 = 아직 없음, 옛 파일은 `serde(default)` 로 0), `Drawing.next_id`(모든 번호보다 큼).
  `Drawing::assign_ids()` 는 0 이거나 앞 객체와 겹치는 번호에 새 번호(겹치면 뒤쪽이 새 번호), `Drawing::index_of(id)`.
- 편집기: 모든 편집이 지나는 `Editor::run` 에서 작업을 실행하기 직전에 매긴다(`run_new`) — 더하는 객체는 번호가 없거나
  이미 있는 번호면 새 번호(복사본), 바꾸는 객체는 원래 번호를 잇고, 묶음은 하나씩 매기며 실행. 매긴 작업이 기록되므로
  되돌리기·다시 하기·변경 기록 재생(§23)에서 번호가 같다. 자르기처럼 한 객체가 여럿이 되면 첫 조각이 번호를 잇는다.
  `Editor::new` 가 `assign_ids` 를 불러 연 도면에 번호를 매긴다.
- 가져오기: 모형 공간 맨 위 객체는 DWG·DXF **핸들**을 번호로 쓴다 — 같은 도면을 다시 가져와도 같은 번호(다른 사람이 고친
  DWG 와 비교할 때 기준이 된다). 한 객체가 여럿으로 펼쳐지면(치수 등) 첫 것만 핸들, 나머지는 새 번호.
- 속성 칸에 「고유 번호」(16 진, 핸들과 같은 꼴).
- 블록 정의 안 객체와 보이는 도면이 만든 객체(블록 펼침·건축 객체 선)는 0 — 번호는 모형 객체만의 것.
- 시험: 열 때 매기기(0·겹침), 더하기·복사 새 번호, 옮기기 그대로, 지우고 되돌리면 같은 번호, 자르기 조각, 파일 왕복,
  다른 편집기에서 온 작업 재생이 같은 번호. 가져오기 번호 = 핸들, 다시 가져와도 같음. 실무 도면(2,118)·10 만 표본 DXF·
  DWG 모두 번호가 겹치지 않고 다시 가져와도 같다.
- 남은 것: 내보낼 때 번호를 핸들로 쓰기(지금은 내보낼 때 새 핸들), 두 사람이 동시에 새 번호를 매길 때 겹침 — Loro 를 붙일
  때 번호에 사람(피어) 몫을 넣는다.

## §83 내보낼 때 객체 고유 번호를 핸들로 (2026-11-26)

§82 의 번호는 가져올 때 핸들을 쓰지만 내보낼 때는 새 핸들이라, DWG·DXF 로 내보냈다 다시 열면 번호가 바뀌었다.
- `export::to_document`: 모형 객체의 첫 DXF 객체 핸들을 그 고유 번호로. 새 acadrust 문서는 기본 표·객체에 0x30 까지의 핸들을
  쓰므로(직접 확인: 0xC, 0x10~0x1A, 0x21~0x30), 새 문서에서 다음에 줄 핸들보다 크고 처음 나온 번호만 쓴다. 문서의 핸들
  계수(`handle_seed`)를 미리 가장 큰 번호 + 1 로 올려 두어, 이 뒤에 만드는 레이어·블록·치수 블록 핸들이 번호와 겹치지 않는다.
- 새로 매기는 번호는 `FIRST_ID` = 0x1000 부터 (처음에 0x10 으로 했더니 새 도면의 블록 참조가 DWG 왕복에서 사라졌다 —
  기본 핸들과 겹쳐서).
- 시험: 번호 0x20(기본 핸들과 겹침)·0x1001·0x5000 인 선을 DXF·DWG 로 내보냈다 읽으면 0x1001·0x5000 은 그대로, 0x20 은 새 번호.
  실무 도면(2,118)·10 만 표본 DWG(91,674) 를 DXF·DWG 로 내보냈다 다시 읽으면 객체 수·종류와 번호가 모두 같다.

## §84 앱의 선택을 고유 번호로 기억 (2026-11-26)

화면의 선택(`SelectTool.ids`)은 모형 목록 번호라, 편집 뒤 앞 객체가 빠지거나 들어오면(되돌리기·변경 기록 합치기·블록
펼치기 등) 같은 번호가 다른 객체를 가리켰다(전에는 목록 길이 밖 번호만 버렸다).
- `selection_info` 가 고른 모형 객체의 고유 번호(`uids`, §82)도 돌려주고, 화면은 그것을 기억한다. 편집 뒤 다시 받을 때
  (`update`) 새 명령 `indices_of_uids` 로 지금 목록 번호를 찾는다 — 없어진 객체는 선택에서 빠진다.
- 사용자가 새로 고를 때(누르기·Shift 더하기/빼기·창 고르기·`set`·건축 객체·고르기 결과 보이기)는 기억을 비운다.
- 배치(종이) 화면에서는 모형 객체가 아니라 쓰지 않는다.
- 앱 확인(Linux 가상 화면): 선 A(목록 0)·B(1) 에서 A 를 지우고 B 를 고른 뒤 되돌리기 → A 가 0 으로 돌아와 B 는 1 로 밀려도
  선택은 B 그대로(속성 칸 고유 번호 1001·시작점 0, 3000).

## §85 변경 이력(Loro)을 파일에 — 서버 없이 사본 합치기 (2026-11-26)

공동작업(M5)의 첫 단계. 동기화 서버 없이도, 같은 `.dsmith` 에서 갈라진 두 사본(예: 두 사람이 각자 고친 것)을 합친다.
- `crdt::Crdt` (Loro 1.19): `entities` 맵(고유 번호 16 진 → 객체 JSON 글, §80 에서 가벼웠던 꼴), `order` 목록(그리는 순서),
  `meta` 맵(객체 밖 필드 이름 → 내용 지문 FNV-1a 64). `sync(도면)` 은 지난번과 달라진 객체·순서·필드만 쓴다(기억해 둔 JSON 과
  비교). 순서는 없어진 번호를 지우고 새 번호를 제자리에 넣으며, 남은 번호의 순서가 바뀌었을 때만 통째로 다시 쓴다.
- 객체 밖 필드(레이어·블록 정의·건축 객체 …)는 내용을 넣지 않고 지문만: 실무 도면은 블록 정의 JSON 이 53 MB 라, 글로 넣으면
  Loro 스냅샷이 상태 + 이력 두 벌로 47 MB, 눌러 넣어도 27 MB 였다. 지문만 넣으면 0.3 MB. 도면을 만들 때(`drawing(사본들)`)
  지문이 맞는 사본의 `drawing.json` 필드를 쓴다 — 필드마다 마지막에 쓴 쪽이 이긴다.
- 파일: `.dsmith` 에 `document.loro`(있으면). `docfile::{to_bytes_with, from_bytes_with, save_with, load_with}`. 옛 파일은
  이력 없이 그대로 열린다.
- 앱: 연 파일의 이력 바이트를 들고 있다가, 처음 저장할 때 Loro 문서로 풀어(없으면 도면에서 새로) 바뀐 것만 맞춰 함께
  저장한다 — 열기는 느려지지 않는다. 편집기를 열 때 새 번호 시작점을 무작위로 띄운다(`Drawing::salt_ids`, 2^40 안에서
  2^18 칸씩 — 두 사본이 새 객체에 같은 번호를 매기지 않게. JS 수·DWG 핸들로 넉넉).
- CLI: `dsmith merge 갑.dsmith 을.dsmith 결과.dsmith`. 이력이 없는 파일이 섞이면 경고(각자 지운 객체가 되살아날 수 있다).
- 측정(release): 실무 도면 — 이력 0.3 MB, 파일 13.6 → 13.8 MB, 저장 0.58 초, 바뀐 것 없이 다시 맞추기 0.1 초.
  10 만 객체 표본 — 이력 6.8 MB(객체 JSON 이 상태 + 이력 두 벌), 파일 1.0 → 5.2 MB, 저장 0.48 초.
  처음에는 필드를 값 나무로 만들고 순서 맞추기가 이중 반복이라 다시 맞추기가 1.2 초·3.1 초였다 — 필드를 글로 바로, 해시로.
- 시험: 갈라진 두 사본(갑 옮기기·더하기, 을 지우기·더하기)을 합치면 모두 들어오고 번호가 겹치지 않으며 어느 쪽에서 합쳐도
  같다. 갑이 레이어 색을 바꾸면 합친 도면에 갑의 색. 바뀐 것만 쓴다, 순서 바꾸기, 파일 왕복.
- 앱·CLI 확인(Linux 가상 화면): 선 하나 있는 파일을 두 사본으로 — 갑은 앱에서 선을 하나 그어 저장, 을은 그 선을 지워 저장 →
  `dsmith merge` 결과는 갑이 그은 선 하나(어느 순서로 합쳐도 같음).
- 남은 것: 앱 안에서 합치기(메뉴), 동기화 서버로 증분 주고받기, 큰 도면의 객체 이력 크기(10 만 객체 5 MB).

## §86 앱 안에서 다른 사본과 합치기 (2026-11-27)

§85 의 `dsmith merge` 를 앱 명령으로: 「다른 사본과 합치기」(`MERGECOPY`·`사본합치기`, 협업).
- `crdt::merge_into(편집기, 이력, 상대 도면, 상대 이력)`: 이력을 지금 도면(저장 안 한 편집 포함)에 맞추고, 상대 이력(없으면
  상대 도면으로 새로 — 이때 「각자 지운 객체가 되살아났을 수 있다」고 알림)을 합쳐, 합친 도면으로 바꾼다.
- `Editor::replace_drawing`: 객체·레이어·건축 객체·배치·블록은 되돌릴 수 있는 한 작업(묶음)으로, 선 종류·글꼴 등은 바로.
  새 번호 시작점은 지금 것과 합친 것 중 큰 쪽(띄워 둔 시작점을 지킨다).
- 시험: 내 쪽은 저장 안 한 새 선, 상대는 첫 선을 지운 사본 → 합치면 [100, 300] 두 선, 되돌리면 합치기 전 세 선.
  앱에서 명령은 실행되지만, 시험 환경(가상 화면)에는 파일 대화상자를 띄울 데스크톱 구성이 없어 고르기 단계에서 취소로 끝난다 —
  고른 뒤의 처리는 위 시험과 같은 함수.
